Hello friends, welcome to Gate Smashers. The topic is File System versus DBMS. In the previous video, we discussed the basic introduction and the definition of the DBMS. But now, the first thing that comes to our mind is which system was used before DBMS, or what was the problem in that system which was removed by DBMS? We can also say: what are the advantages of DBMS that allowed it to replace the old or traditional system? 

Here we are talking about the file system, which means the file system was used before DBMS. Now, file system does not mean it is not used in today's time. I am explaining it with a very small and real-life example: in the 1970s scenario, how was data accessed? As a user, the data is in my system, and I am accessing that data. As a user, I am saving the data and I am only using the data. Now, in this case, we can use a file system because the user knows how to manage data in the form of files, so it is very easy for me to make my own drives. As we see even today, what comes in our laptop? A file system. It is inbuilt in the operating system, such as CIFS or NFS file systems. What happens in them? Whatever data is yours, you put that data in the form of files; we create drives, create folders and subfolders in the drive, and store data in a hierarchical form. That is the use of the file system. 

But then why are we using DBMS when the file system is running properly? Why are we using the DBMS? Because we are now using client-server architecture. Client-server architecture means my data is not only with me; I am not only accessing my data, but my data is at a centralized location, and users all over the world are using that data. If I show it with a simple diagram: it is my server, my data is with this server, and many users are attached to this server who are present all over the world and trying to access that data. Now, in this case, where my users are present all over the world, when they are using the data, we cannot use the file system; we have to use DBMS. 

The reasons are the points of comparison between File System and DBMS.

**1. Searching and Data Retrieval**
The first point is when we search the data. For example, if we talk about IRCTC, if we are searching for a train in IRCTC—let's say I am searching for data of 1 KB, which means I have to find the details of a particular train. Now, if the file system is used there, then actually what will happen? I will get the complete file—whose files? The entire train data. Means I just want to search 1 KB of data, but how much data is coming to me? Approximately 25 GB, just for example. 25 GB of data is traveling, and it will take time. 25 GB is coming into my system, unnecessarily memory is being used, and out of that data, I have to search only 1 KB of data, which is a very complex thing. 

That is why now comes the concept of DBMS. What does the DBMS do? Your 25 GB data is with the server—meaning the entire data is with the server of Indian Railways. Now, what will the user do? They will write a simple query using SQL, and on the basis of that query, how much data will come to them? Only 1 KB. That is the first point. Here, my searching is fast, and the utilization of memory is also efficient.

**2. Attribute Requirements and Independence**
The second point is that whenever we search for data using the file system, we require attributes. I need that file name, file location, file permissions; like that, I am accessing data. I need metadata of that data first. When I get that metadata—what is metadata? Data about data, meaning the data about the particular file—I first need that data. Like we normally access a file in our system, then the location comes: `C:/folder 1/folder 2`. That is a location. I can access that data only when I have it. 

But in DBMS, there is no location; it is totally independent. Independent means the user does not know where the data is actually stored. The user will write just one query from their laptop or system by using any platform. What can that platform be? It can be any web application, like we do in IRCTC. We open the IRCTC web application or mobile application, and on that application, we send a request. That request goes to the server, the server responds, and I don't need any attribute to respond. I just want to access the data, and there is no requirement for attributes to access that data. So my searching here has easiness; DBMS is providing easiness here.

**3. Concurrency**
Third point is concurrency. What is the meaning of concurrency? In today's time, the most used concept is concurrency, meaning concurrent access—multiple people at the same time accessing the data. This is the most important thing in today's time. If we talk about IRCTC—I am discussing the example of Indian Railways because DBMS is a bit of a theoretical concept in the beginning, but if we give a real-life example with every concept and understand this real-life example, then you will never forget this concept. 

Now we are talking about concurrency. In our system of Indian Railways, if we are booking a train, then what do you think? You alone are using the Indian Railways system at that time? No. I had read in a survey, and according to that survey, there are 2 to 3 lakh transactions every day on IRCTC's server. Now, so many transactions are happening, meaning 1k-2k transactions are going on at a time. At this time, so many users are accessing the data; this is called concurrency. 

And there is no protocol for concurrency in the file system, meaning if thousands of people access the file at the same time, then there may be inconsistency in the data. But the DBMS provides proper protocols. It has protocols for concurrency. Like, if two people are doing read-read, there is no problem. Doing read-write at the same time: there is problem. Write-read: there is problem. Write-write: there is problem. All of this we will do in detail when the topic or unit of transaction control and concurrency comes. Right now, you only need to know this important point: for concurrency, protocols exist in DBMS, but no protocols exist in the file system, due to which problems are created.

**4. Security**
Fourth point is security. Yes, security is again a very important issue nowadays. What is the meaning of security? If I am accessing data here, then can anyone access the same data, or should there be some role-based work here? Role-based means: like we talk about a university. If I am teaching in the university as an assistant professor, students are also there, assistant professors are also there, admin people are also there, and the dean is also there. So, the data I am accessing—are students also accessing the same data? Is the dean also accessing the same data? Or is there any hierarchical security? Hierarchical means we call it role-based security. 

What is the meaning of role-based? If I have some data, then to access that data, I will create different roles. A student is a kind of user—you can call it a user role created or user created: a student, a faculty, and let's say a dean. Then everyone has their own role base. We call it role-based access control, and it is very important in today's time. If you are on any website—let's say if you are filling any form on the website of the Indian Army for SSB—then what do you think? Can you check any information there? No. There is a separate role for authenticated people or users, and there is a separate role for you. So the data they want to show you, only that much data will be visible to you; the rest of the data for you is invisible. That is the reason I am getting security here. 

But there is no such scene in the file system, because who handles the file system? The operating system. And in the operating system, there is no hierarchical security—hierarchical means level by level. There is no such security. How does the operating system provide security? When you turn on the system, a password comes; as you enter the password, the system turns on. When the system turns on, you go to any drive: go to C, go to D. This is from the user's point of view. When thousands of people will access that data, then there is no security protocol in the file system. But DBMS provides role-based security; you can create different users, you can create different roles, so that only that much data will be visible to the particular user. The rest of the data—they will feel that it is not there. But yes, the rest of the data will be available; it will be available in some other role. So that's why security is a very important concept, and this aspect is provided by DBMS, while the file system does not provide it.

**5. Data Redundancy**
Fifth one is data redundancy. Redundancy means duplicacy. Data duplicacy means I am saving any data in a file. I stored the same data four times. Let's say I am making an Excel file. There is a student Ram, and his roll number is 1. I have "1 Ram, 1 Ram, 1 Ram". When the student is only one, then why are you storing his data four times? But in a file system, there is no such check. Yes, the operating system will check that if you are not storing the same file twice with the same name, but if you change the name, then you can store that too—meaning multiple files with different names you can store, but the content will be the same. 

However, in DBMS, there are a lot of constraints. There are constraints of primary keys, there are constraints of foreign keys, which help in data integrity. So these different constraints ensure that the data is not redundant, and that I can store only unique data. 

**Conclusion**
This is how DBMS is superior to the file system. And this is the reason that in today's time, for all client-server architectures and web applications, what do we use at the backend? DBMS. What is on the frontend? We are there, the users. We use any application—use Flipkart, Amazon, Google—who are we? Front-end users, using data. But what is on the backend? DBMS, which handles the data, the request, and responds to that request. 

So these are the major points which can be called disadvantages of the file system or advantages of the DBMS. This is all about the difference between the file system and DBMS. Thank you.
