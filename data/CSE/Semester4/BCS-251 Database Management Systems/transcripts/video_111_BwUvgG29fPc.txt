### Purpose of B-Trees and B+ Trees

Firstly, if we talk about B-trees and B+ trees, why do we use them? We use them to hold index records. It actually contains index records. Now, what is an index record? Two things are there: a key point and a data pointer. 

A key means the basis on which we are searching, and a data pointer means the data related to the key and where it is present in actuality. For example, if we talk about a book, at the starting of the book, there is an index. Now, in the index, there are two things: the broad topic or main topic and its page number. If you want to search what is there inside the topic, you have to go to that page, and then you'll get the data. 

So here, in the data, I have only two things: a key and a data pointer. Actually, there is no whole database present here; only two things are there in an index record: a key and a data pointer.

### Structure of a B+ Tree

Now here we'll talk about the B+ tree structure—meaning how the structure of a B+ tree is. The structure of every node in a B+ tree is different from the B-tree. 

Here, the biggest problem in a B-tree is that data—meaning keys and record pointers—is present everywhere. It is present at the root also, in internal nodes also, and in leaves also. This means the key you are searching for, you can get a data pointer anywhere corresponding to that key. If we have a B-tree like this—suppose if we make a simple one—if we are searching for a key, you can get the key here also, you can get the record pointer here also, or anywhere in the whole tree, because the key and data pointer are distributed in the whole tree. 

But it is not the same in a B+ tree. In a B+ tree, if we talk about the internal node, what have we done with the internal node structure? What is in an internal node? So in an internal node or non-leaf structure, we have block pointers (as it is non-leaf, so there must be children which are pointed to there), children, and with that, we *only* have keys. In this way, you have the structure of an internal node in a B+ tree. So what have we deleted from the internal node of a B+ tree? We removed all record pointers. So all record pointers are removed from here. Because of this, you can say that we have vacant space. So we can create more and more children—meaning we can put more and more keys, and more and more block pointers we can put. 

Because of this, a B+ tree is more breadth-wise, because if children are more, it will grow breadth-wise. And if we talk about a B-tree, it is depth-wise more, because we've inserted more in this; if we fill it more, obviously we'll have less space for block pointers, and thus the number of children will reduce as compared to the number of children in a B+ tree. Because a B-tree is depth-wise more, obviously searching—because data is present everywhere and index records are everywhere—searching will be slower, or deletion will be complex, obviously because of this reason.
