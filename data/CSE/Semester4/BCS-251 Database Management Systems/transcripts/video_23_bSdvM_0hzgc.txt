We are going to discuss the closure method. The closure method is very important in DBMS because this method helps you to find all the candidate keys in the table. This means if you have a table given and you need to find all the possible candidate keys in that table, you have to use only one method, which is the closure method. We are talking about tables in which you might not have been given attributes that we normally use, such as SID or student name; a general table will be given. 

Let's start with an example. Suppose there is a relation, which means a table. There are four attributes in the table: A, B, C, and D. They have given the functional dependencies: A goes to B, B goes to C, and C goes to D. These three functional dependencies are given. 

Let's start with the closure method. What you have to do is take the first dependency, A. We denote it with $A^+$, which represents the closure, so we are finding the closure of A. The meaning of closure is: what can A determine? What can A determine? We already know A is determining B. From the functional dependency, you can clearly check that A is determining B. So I wrote the closure of A is B. 

Now, B is determining C. This means B is determining C, and A is determining B. This is an example of the transitive property. What is the transitive property? If A determines B and B determines C, then since B is common, you can clearly say that A can determine C through B. So A is determining C over there. That means here A will determine both B and C. 

Next, C is determining D. You will have to check very carefully that if C is determining D, then A can also determine D through the transitive property. And the last important point is that A will determine itself because of the reflexive, self-loop kind of property. A is kind of like a roll number. If I say A is a roll number, a roll number can determine itself. A student's name can determine itself. So A is determining itself. Other than that, what else does it determine? B, C, and D. 

So when we check the closure method, now let's check which attributes came in A's closure: A, B, C, and D. Check which attributes are in the table: A, B, C, and D. This means A can determine all the attributes in the table. This is the property of a candidate key. A candidate key is a key such that if you are having confusion with any number of columns in the table, you can get them determined by the candidate key. So here, clearly I can say that A is a candidate key in the table. 

If we make the set of candidate keys, I got the first answer here, which is A. But don't stop here, because the rule of candidate keys will be used in the second normal form, third normal form, and BCNF, where you have to find all the candidate keys in that table. 

Let's start with $B^+$. If we check the closure of B, as we already know, B can determine B because it is reflexive; it determines itself. Now, check the functional dependency. In the functional dependency, B can determine C, which means B is determining C. This is a direct dependency. If it is direct, we can directly write it. And since C is determined by B, and C is determining D, through transitivity, B is also determining D. But see, here B is not able to determine A. This means B determines B, C, and D, but B is not able to determine A. So it means B cannot be a candidate key. 

The same goes for C's closure. C is determining C, and C is determining D. So you can say C determines C and D. Similarly, D is determining only D. Apart from this, it is not determining anyone. So neither C can be a candidate key nor D can be a candidate key. Therefore, there is only one candidate key in this table, that is A. 

Guys, here you have to be very careful. Many times, we check the closure of two attributes by combining them, such as AB.
