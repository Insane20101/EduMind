Candidate key is a very important concept of the database. Before discussing the candidate key, we need to know about the key—only the key. First of all, what is the key? A key is a normal attribute. For example, if I take a table, like I have a student table. In the student table, we have student name, student city, and age, and I have inserted some rows. A key is one of the attributes from the table, but what is the use of a key in the table? A key is used to uniquely identify any two tuples in the table, to uniquely identify any two tuples in the table. 

For instance, if I have exactly two same rows in my table, if I have exactly two same rows in my table, then here comes the confusion, guys: maybe it is the same student whose information is repeated twice by mistake, or it is two different students and by coincidence both of their values are the same. When we use a database online, when we use a database online, it is very difficult to identify whether it is the same guy which is written twice or two different ones. So to identify this, we should have a key in the database. 

If I talk about the student table, let's take a normal example of a student table. A student table can have many attributes like student name, student's ID, student's father's name, student's mother's name, student's address; we can have multiple attributes. But what can be the key? A key means an attribute which can uniquely identify any two tuples, showing whether those tuples are different or the same. 

We can have the Aadhar card of the student, roll number of the student, registration number of the student, registration number, student's license number, voter ID, and there can be more, guys, like the student's phone number. I am writing all those attributes which can uniquely identify any two rows. If I add a column in my table for roll number, then the value of roll number can never be the same in the table. So if some values are the same across other columns, there will be a column in which the values will be different. If I am confused here whether these two "Reddy" entries are two different students or the same student, I will check their roll number. As I see the roll numbers are 1 and 3, I get definite surety that they are two different students, but coincidentally they are from the same city and from the same age group. 

Similarly, guys, we can use the Aadhar card, we can use the license number, we can use the voter ID, we can use the phone number, and apart from this, guys, we can use the email ID. We can use the email ID because the value of all these can never be repeated. If the roll numbers of two guys are different, the licenses of two persons will always be different, the voter ID card numbers of two persons will always be different. Similarly, the PAN card number will always be different. 

All these values—the 1 to 7 columns which we have written, the 1 to 7 values—if we see the set of all these, then this entire set, we can call them candidate keys. Aadhar card, voter ID, license number, roll number, phone number, email ID—the collection of all these will be known as candidate keys. The collection of all these can be called the candidate key set. 

Out of this candidate key set, we choose one key which is the most appropriate, and we make it the primary key. The rest of the keys remain and are known as alternative keys. That means, from where do we choose the primary key? The primary key is chosen from the set of candidate keys. The student has to understand very carefully how to design the complete set of candidate keys and, out of that, how we have to use the primary key, because the primary key is very important.
