But what is the meaning of "related data"? 

For example, we talk about Indian Railways. IRCTC has its own database, a very big database. Now, what will happen in that database? What happens when you log in? First of all, you search for the information of the train if you want to go somewhere. Apart from that, what will IRCTC have? What I am trying to tell you here is that a database is a collection of related data. It is not that we club any data together. For example, Indian Railways cannot club the data of Indian passports with their data; they have their own database of passport holders, and Indian Railway people have their own database. That is why it is related data. 

Now, here I have further bifurcated it. Generally, data is categorized as structured, semi-structured, and unstructured. But actually, if we talk about DBMS, today it doesn't go into so much detail in GATE or UGC NET, but you should know about what structured data and unstructured data are. 

What is structured data? It is such a database which I can store in any particular shape or in a particular structure. Unstructured means which has no particular structure. I have written a simple example here: Indian Railways data or university data. Why are university data or railway data structured? Because there is a particular structure for them. Which structures? The most important structure used for structured databases is RDBMS (Relational Database Management System). 

Now I am coming to this term: Database Management System. We save the data—meaning I have a lot of data, and I saved the data in the backend, in hard drives, on servers. Now, what to do with that data? Obviously, users will search that data, users want to access the data, and they will do some updates in the data, insert some new data, or delete some old data. This means they have to perform operations on average: insertion (some data has to be added), deletion (some data has to be deleted), and update. Update means some old data, like the address of a student, was something else, and it has been updated, meaning it has changed. We call all these things operations. 

I should have some system to perform all these operations, and that system is called a Database Management System. So, a Database Management System has a collection of operations which provides easiness to the users so that the users can easily perform operations in the database. Which operations? Insertion, deletion, and updation. 

Now, where can the data be? The data may be in a remote area. For example, if I am sitting in Delhi, where is my data stored? In Mumbai. I have nothing to do with the location; I have to access the data and make some changes in that data. For example, we access the data of IRCTC and make reservations for a train. Do we know where that data is stored? No. Because users have nothing to do with it; they just have to perform their operations, and the DBMS helps them to perform those operations. 

Now, we also have various DBMS options; different companies have created different database management systems. If I give a simple example, Microsoft Corporation has made SQL Server. Oracle people have also made different versions of SQL Server (2005, 2008, 2010, 2016, various different versions). Similarly, Oracle has 2009, 2011, 2012c, 2016, with different versions. Now, here we are talking about structured data. I am only focusing on structured data out of this whole discussion because, as I told you, structured data is such data that has a proper structure to store the data, and that structure is a relation. Relation means a table. We store structured data in which format? In table format. Table means—even if you do not know about it, no problem, I am explaining it from a very simple point of view—if you have seen an Excel file, there are columns and rows; you can compare that with it. What is a table? It has some columns and different rows. 

Technically, we call this table a "relation." But my point is how we store structured data. Structured data can have different ways, but the most usable method is relation—how to store data in relation form, in table form. 

Now, when I am storing data in the form of a relation, obviously I also need some management system; I need some platform that supports the relation. Whenever the user accesses the data, it shows the relation. Whenever users store data, it goes and stores the data in the relation, like IRCTC. If you remember ever logging into IRCTC, you first check it by entering the source and destination, and you get the information of all the trains. It comes in which format? It comes in a table format, in which the first column is train number, train name, and also different things like number of compartments, type of seats, departure time, departure date, etc. Different databases have their own columns, but we are not talking about that right now. 

We are talking in a simple format, and whom am I talking about here? Only structured data. In GATE also, questions come from this; in UGC NET, even in all competitive exams, questions come on structured data and how to store structured data—in the form of relation. 

Now, storing the relation and accessing it—what do I need? A management system. So what is a DBMS? A management system, but for whom? For relations. That is why a new term has come from here: RDBMS, that is Relational Database Management System. So this is our subject, i.e., Relational Database Management System, a system where we can perform insert, delete, update, and many operations, but on whom will we perform them? On relations. So this is the basic introduction of the RDBMS.
