First of all, tuple relational calculus is a non-procedural query language. Whose part is it? It is a part of relational calculus. In relational calculus, two types of languages come: tuple relational calculus and domain relational calculus. In tuple relational calculus, its main focus is on tuples, which are our rows. Now, in domain relational calculus, its main focus is on columns, which we call attributes. 

Here, tuple relational calculus is non-procedural. Non-procedural, I have already told you, is where we tell what to do, but how to do we do not mention. If someone asks you what the difference is between relational algebra and tuple relational calculus, the first difference is that tuple relational calculus is non-procedural, and relational algebra is procedural.

In tuple relational calculus, we use first-order logic fundamentals, and every query is written like this: 
`{ t | P(t) }`

What is the meaning of `t` here? It is the resulting tuple, meaning the final tuples you have as the answer. What will be the answer? We represent it in this way with `t`. 

And what is `P(t)`? It is a predicate. It is a rule, or you can say a range, where we give conditions. Whichever tuple satisfies this `P(t)` will come in the final output. That tuple will come which will satisfy this condition; which will not satisfy will obviously not come in the final result. 

What does this basically do in tuple relational calculus? Let's say if you have a table, what is there in a table? Multiple tuples. What does it do first? This small `t` I am talking about, what is this? This is a variable. This variable starts from tuple 1, then tuple 2, tuple 3, tuple 4. What does it do? It examines all the tuples. 

And on what basis does it examine? That condition, that predicate we give here on the right side. The condition we give in this range, we will give all the conditions in that range. Corresponding to all the conditions, whatever will be true, the tuples which will satisfy will come in the result, and which do not will not come in the result. This is a basic fundamental of tuple relational calculus.

Next, I talk here about operations. Same as we use in relational algebra, the same operations we can use here also, but there the operations are different. Here, if you talk about like `or`, `and`, `not`, apart from that, here we talk about atomic functions. 

What is the meaning of atomic functions? Which work on one tuple. One variable we use in it. Like, let's say a supply table is given to you. But if you are giving more than one condition, then it does not remain atomic; it becomes a composite formula. 

Apart from this, if we talk about quantifiers, we use two: "there exists" ($\exists$) and "for all" ($\forall$). 

What is the meaning of "there exists"? As we normally discuss in first-order logic, what is the meaning of "there exists"? There exist some tuples, and which tuple belongs to this particular condition, which satisfies this condition in the whole table? There is a row.
