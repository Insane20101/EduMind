### Understanding Promises

First, let's understand what a promise is. We have already discussed callbacks, where we pass a function into another function and call it from there. This is a callback. 

A promise, on the other hand, is a promise of code execution. I will toggle word wrap and show you what a promise looks like. I will set up a script tag with `src` pointing to `script.js`. Suppose I have a function called `getData`, which will bring data from the server. However, we don't know how long it will take to retrieve this data. 

For example, I might have a console log that says "loading modules." While my code is running from top to bottom, I need to load data and then process it. But I want to wait for the data to load before processing it. 

To achieve this, we can use a promise. We can say `let data = getData()`. This function will return a promise, which is an object that will eventually contain the data once it is retrieved. The promise can either be fulfilled or rejected due to a network error.

### Simulating a Promise

To simulate a promise, I will return a new promise. I will use `setTimeout` to mimic a delay in data retrieval. For example, I will resolve the promise with a random value after 3 seconds.

The benefit of asynchronous JavaScript is that while the promise is pending, the code below it continues to run. If I set the timeout to 53 seconds, you will see that everything prints out, but the promise remains pending until it resolves.

### Using `async` and `await`

Now, I want to ensure that my code waits for the data to load before proceeding. One way to do this is to use `data.then()`, which allows us to run a function when the promise is resolved. However, this is a callback-based approach, which can lead to nested code.

`async` and `await` were introduced to provide a cleaner way to handle asynchronous operations. By marking a function as `async`, we can use `await` to pause execution until the promise is resolved. 

I will create an `async` function called `main` and wrap my code inside it. When I call this function, it will run in the background. If I use `await` before the promise, it will wait for the promise to resolve and return its value.

To demonstrate this, I will format the document and run the `main` function. When I reload the page, you will see that the promise is pending, but the code execution continues.
