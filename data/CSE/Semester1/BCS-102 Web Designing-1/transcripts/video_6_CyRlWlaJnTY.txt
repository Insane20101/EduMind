**Understanding Core Web Vitals**

The first Core Web Vital we will discuss is Cumulative Layout Shift (CLS). CLS measures how much the layout shifts while the page is loading. For example, if a user is trying to cancel an order and the layout shifts unexpectedly, it can lead to a poor user experience. To minimize CLS, you should define the width and height of images so that the layout remains stable during loading.

The next metric is Largest Contentful Paint (LCP). LCP measures how long it takes for the largest element on the page to load. For instance, if the largest element is an image, LCP measures the time taken for that image to load. According to web.dev and Google, a good LCP score should be 2.5 seconds or less.

The third metric is First Input Delay (FID). FID measures the time it takes for the browser to respond to the first user interaction, such as clicking a button. Google recommends that this input should start processing in less than 100 milliseconds.

These three Core Web Vitals are essential for your website's performance. While they may be updated over time, they remain crucial for SEO.

**Using Lighthouse for Performance Analysis**

Now, I will show you what a Lighthouse report is, why it is generated, and how to assess these three Core Web Vitals. To access Lighthouse, right-click on the page and select "Inspect." You can adjust the panel's position as needed. You will see the option for Lighthouse, which generates a report indicating what can be improved on your HTML page.

If I want to see how mobile users experience my website, I will select the mobile option and click on "Analyze Page Load." Lighthouse will generate a report covering performance, accessibility, best practices, SEO, and PWA (Progressive Web Apps). You may notice some items highlighted in red, indicating areas for improvement. For example, it might suggest that properly sizing your images can improve loading speed.

Lighthouse will also indicate if image elements lack explicit width and height. Setting these attributes in HTML reserves space in the browser, preventing layout shifts during loading. If width and height are not set, the browser cannot determine how much space to reserve, leading to potential shifts in the layout.
