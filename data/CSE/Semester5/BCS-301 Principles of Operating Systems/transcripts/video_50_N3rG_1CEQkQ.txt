Various allocation methods in Contiguous Memory Management. We are using four algorithms for how we allocate memory to processes. In our memory, as many processes are already present and as many available holes we have, how we allocate processes in those holes. There are four algorithms: First Fit, Next Fit, Best Fit, and Worst Fit. 

Let's examine this according to the diagram. This is showing a process has already occupied this memory area. There is already a process, let's say process 10, process 11, process 12, process 13, process 14, and process 15. These processes are already there in the memory, and this is representing the holes, meaning leftover space. How can we manage this leftover space? We will be using these algorithms.

Let's start with the first one, the First Fit algorithm. According to the First Fit algorithm, allocate the first hole or partition—we can say partition also, but the majority of the time we use it to manage the holes. Allocate the first hole that is big enough. Let's say there is a process P1, and the process size is 15KB. If a process of 15K is coming, according to First Fit, what will it check? It will simply check the first location that is big enough which can hold the 15K. It will start from this; this is already occupied, occupied, occupied, and this is the empty space. What is the size of this hole? 25K. 25K can easily accommodate the 15K. According to First Fit, it will simply stop searching hole searching will stop—and simply allocate P1 to this partition, or we can say hole. Where will it accommodate P1? In this space. The first such hole where I can fit that process, that we call the First Fit. It is the easiest because here my searching time is also very less. I am not searching the entire list; when I get the first hole, I will accommodate the process there.

According to Next Fit, Next Fit is a modified version of First Fit. In Next Fit, we are doing the same as First Fit, but we always start searching from the last allocated hole. The last allocated hole given to some process, we will keep a pointer on that. According to First Fit, I put P1 here, so I allocated P1 here. Now, I will keep a pointer at this area. That pointer will help with what? Next time if a process comes—let's say another process comes, P2, and the size of P2 is 18K—from where will it start searching? It will not start searching from the beginning. It will start searching from the last value or last space where the process was allocated. Where was it last? On this hole, so it will start searching from here and check whatever is next. Let's say 40K is enough; in 40K, we can easily put 18K, so this area will be taken by P2. The advantage of Next Fit is that we do not need to search from the beginning again and again. Whatever last hole I gave to some process, from that hole we will start searching for the next empty hole so that I can accommodate the next process in it. Here, according to Next Fit, I will again not start from zero to search. Where will I start from? From this hole, because this hole I had already given in First Fit, so I will next start from 40K. In 40K, I can easily accommodate a process of 18K, so I will put P2 here. This is the concept of Next Fit.

The third one is Best Fit. What is the concept of Best Fit? From the name, it is clear: it will search the entire list, and it will try to search for that hole which will lead to minimum internal fragmentation. Let's say my process size is 15K. According to First Fit, I can put a 15K process in this hole. According to Next Fit, I can also put it in this hole. But according to Best Fit, although 15K can be accommodated in this hole, it will search the entire list. Let's say 40K; it can be accommodated in 40K also, but the leftover space is very huge. The remaining portion should be minimum; it will try to search for that hole. So at last, where will it come? In 20K. Can 20K accommodate P1? Yes, 20K can accommodate P1 easily. And what is the leftover space? If P1 is allocated here, how much is my leftover space? 5K, because the remaining area is taken by P1. So it will search the entire list, it will search all holes, and choose that hole in which if I put that process, then the remaining portion will be least. This is the concept of Best Fit, so that my internal fragmentation should be minimum in that case.

According to Worst Fit, what do we do in Worst Fit? We simply select the largest hole. In this also, we will search the entire list, but in which hole will we put the process? Where my leftover space is maximum. This is the exact opposite of Best Fit; it is the reverse of Best Fit. If the size of P1 is 15K, I can put it here, here, or different places. But according to Worst Fit, where will I put P1? In this hole. When P1 is put here, how much is the remaining portion? The rest of the portion is 85K, which is leading to the maximum memory leftover. According to Worst Fit, where do we put any process? Where my left space—after putting that process, my hole size—is very big.

Now, if these are compared, First Fit is the easiest method. It is very simple to implement and very fast. The advantage is that it is very fast because it is directly searching for the first hole that is big enough to hold my process. It has nothing to do with whether the leftover space is high or low; if a process can be accommodated by a hole, the first hole found, it will allocate that process in it. The advantage is that it is simple and fast. But what is the disadvantage here? It is possible that the remaining portion—the remaining hole, let's say if I accommodate P1 here, then the remaining portion will create holes; it can create big holes. If I put 15K here, how much remaining space do I have? A further hole of 10K remains. Now, in this 10K hole, if some process of 10K comes, I can accommodate it in this, but if processes of large size are coming, I cannot accommodate them in this.

Next Fit is the same as First Fit, but with one more advantage. First Fit will always start searching from zero; as soon as the first hole is found, it will put the process in that. But in Next Fit, we made it a little faster. How did we make it fast? As soon as we put P1 here, we put a pointer here. Now, the next time when we search for some hole, we will start searching from this point; we will not start again from zero. So in Next Fit also, when one more process of 15K comes, which is the next hole found? This hole. What is the size? 40K. And what is the size of my process? 15K. So I can easily put the 15K in this.

The third one is Best Fit. What advantage do I get here in Best Fit? Internal fragmentation will be very less. The portion that will be left afterwards will be a very small portion. But in a way, this can be a disadvantage also. Let's say a process comes, and the size of the process is 35K. According to Best Fit, I can put it in this slot, or I can put it in 100K also because 100K can also accommodate it. But Best Fit says that after putting a process in the hole, the remaining space should be the least. According to that rule, I will simply put this process, let's say process P2, into this hole. What is the remaining portion left? Only 5K. So many times, what Best Fit does is create such small, tiny holes that I may not be able to further accommodate a process in them. Because in such small holes, it is possible that my process may not fit, since process sizes are a bit larger and there are tiny holes. In those tiny holes, I cannot put the process. But if we see from a normal point of view, we are basically searching for such a hole in which my internal fragmentation is lowest.

There is one more big disadvantage in Best Fit: it will search the entire list. It will search the entire list to know in which hole to put that process so that the leftover portion should be least. To know this, it will have to compare everywhere. If P2 size is 35K and hole size is 40K, the leftover portion is 5K. Next is 100K; if P2 size is 35K and hole size is 100K, the leftover portion will be near about 65K, which is huge. So it will search the entire set of holes and then decide in which hole I have to put the process so that the leftover portion is least. For Best Fit advantages, we can say that internal fragmentation will be less, or the remaining holes will be left in very small portions. But if we look at its disadvantages, it is very slow. This is very slow because it will search the entire list.

Worst Fit is also similar. In Worst Fit, what are we searching for? For such a hole in which my remaining portion is very high. If a process comes—let's say the size of the process is 20K—where will we accommodate a 20K process according to Worst Fit? We will simply accommodate it here so that when we put this 20K here, how much is the remaining portion I have? 80K. In Worst Fit, an advantage is that although it is searching for that hole which is big enough and which is leaving the maximum leftover space, here the maximum leftover space is 80K. This space is large enough that if one more process comes, or two or three more processes come, I can accommodate those here also. Here, I don't have small portions left of 1-2 bytes or 1-2 kilobytes in which I cannot put the process. Where was this problem coming? In Best Fit. But in Worst Fit, a big 80K hole is left. Now in this 80K hole, let's say process P2 comes with a size of 10K. According to Worst Fit, I will again put this 10K in this 80K hole, so that my leftover portion will be the biggest, which is 70K. There are chances of putting more processes in it. But in Best Fit, when you put a process, the remaining memory is so small that the chances of putting further processes in that remaining hole are very low. In Worst Fit, the chances are still there because the remaining portion is still enough that you can accommodate another two or three processes. 

Here also, what is the problem? It is slow. Why is it slow? Obviously, it will also search the entire list. After searching the entire list, it will decide in which hole to put the process so that the remaining space is highest and maximum. In Best Fit, the remaining space should be minimum, and in Worst Fit, the remaining space after putting the process should be maximum. Best Fit and Worst Fit are exact opposites.

If we look at real life, we can say that First Fit is the most convenient method because if we simply talk according to time, among these four—or basically among these three, since Next Fit is a modified version of First Fit—we can overall compare First Fit, Best Fit, and Worst Fit. First Fit is the most convenient method because the time taken is least. But if you normally get a question, any scenario may be there. Maybe Worst Fit works best, or maybe First Fit works best, so you don't need to cram this, but how these algorithms are actually working, that is the important thing.
