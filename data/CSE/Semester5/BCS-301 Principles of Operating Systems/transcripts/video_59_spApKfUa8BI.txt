Hello friends, welcome to Gate Smashers. The topic is inverted paging. Inverted paging is totally different from normal paging. Let's see the comparison between internal paging and normal paging. 

So what have we done in normal paging till now? We divide processes into different pages and bring some of their pages into main memory. When the CPU asks for a page or process in main memory, we first find it in the page table. From the page table, we know which page is lying in which frame number. Because for each and every process, we keep a page table. And in that page table, we have to find those pages first. Let's say this page table is of P2. When the CPU will say "I need this page", let's say page number 1, page number 1 is lying in frame number 1. Page 1 of the P2 process is lying in frame 1 of main memory. We will fetch the data by going there. 

In the same way, the page table of P1: what am I getting in page table P1? P1's process 0, or page number 0, is lying on frame number 0. We have to maintain a page table of each and every process. This is the concept of normal paging. In each and every process, there is a page table. And where is that page table actually stored? Normally, they are stored on a hard disk. But as soon as any process has one or two pages come inside the main memory, we also have to store their page table in main memory. 

Here, two points are very important. The first point is: each process has its own page table. Each process has its own page table. And the second point is: where will the page table be? Let's say I have 10 processes. If I have 10 processes, then there will be 10 page tables. If each process has even one page lying in main memory, we have to keep its page table in the main memory too. Because first of all, I have to find the page table; I will know from the page table only if the page I am looking for is lying in which frame. So we have to keep the page table in the main memory. So these two points are very important in normal paging. The page table will be in main memory. So the page tables will be in some frame of the main memory.

The problem is that if I have 10 processes, each process has its own page table, and each process has one or two pages lying inside the main memory, meaning it will take me 10 frames to store only the page table. Because the page table of 10 processes will be lying in the main memory. Because some pages of 10 processes are lying in the main memory, those page tables will have to be mounted in the frames of the main memory. 

The problem here is: we have already discussed that main memory is limited. If the main memory is limited, then the number of frames is also limited. And in a limited number of frames, instead of storing data, instead of inserting pages, I am using some frames only for page tables. 

This thing was removed by inverted paging. What inverted paging says is that instead of keeping all the page tables for all the processes, there will be only one page table. Meaning, we will create a global page table. The operating system will maintain the same page table throughout the system. And that page table will be maintained like this: if there are 100 processes in my system, in normal paging, there will be 100 page tables. And if pages of 100 processes are lying in main memory, the 100 page tables will also have to be kept in the main memory. This is becoming too much wastage of memory. 

To utilize it properly, we will create a global page table. The global page table will be maintained by the operating system. What will be inside it? Page number, process ID, and frame numbers, meaning it is totally opposite. If you compare this, this is an inverted page table and this is a normal page table. The outer index of the normal page table, which we call indices, is denoting page numbers, and inside it is denoting frame numbers. Here it is reversed, which means that what was inside was thrown out. Indices of the outside will show frame numbers, and inside it, I have page numbers. 

And here is the first point that came up: what will be the number of entries here? How many numbers of entries will there be? The number of frames will be in the main memory. Let's say there are 1024 frames in the main memory. So what will be the number of entries? What will be the number of entries in the inverted page table? 1024. As many entries as there are, we have to maintain the same number of frames up to 1023. Inside it, I am keeping page numbers. Here the page numbers used to be out; I have kept those pages inside. 

Now what are these pages denoting? This is Page 0, Page 1, Page 2, Page 1. Now here you must be getting some confusion, that page 0 and page 1 are here, and page 1 is there also. Obviously, if you're dividing any process into pages, there is a chance of getting page 1 in each process. Like we have divided these three processes into pages: here is also page number 1, here is also page number 1, here is also page number 1. But this page 1 is of process P1, this page 1 is of process P2, this page 1 is of process P3. Here, if I write only page numbers, let's say page number 1, page number 1: when we will search, CPU will generate a logical address, and that will tell me which page I am looking for. I get to know that I am searching page number 1. Page number 1 is of which process? It is also important to find out. There will be multiple pages here. There can be many page number 1s, but which process that page number 1 belongs to, that is also necessary to find out. 

So that's why there will be two things inside this page table: page number and process ID. So page table entry, what we have seen in the normal process in paging, in that the mandatory field was only one, that is frame numbers. Apart from that, there were other things like protection bit, cache, etc. There were lots of other values; you can check my other videos related to the page table entry. But here, two things are mandatory. There was only one thing mandatory in normal paging, and that was the frame number, and here it is two. One is the page number, and what process is that page of? That is also important to find out. Because whenever the CPU will say "I need process page number 1", by which process do I have to take that page 1? I will also have to mention this here. I have to mention each and every page along with their whole process numbers. 

Now the next point is searching. If the CPU is searching page number 1—page number 1 of process 3, or let's say page number 2 of process 3—how will I find page number 2 of process 3? Obviously, I have to use a linear search here. I have to check every single entry properly because there is no other option. I have to search each and every option linearly. The problem of the inverted page table is searching time. In the normal page table, we used to find out directly: "Page number 1", so I went to page number 1 of that process, and I got to know directly through the frame number. But here, first I have to find which page they're talking about. They are talking about page number 2, and that page number 2 is of process P3. When I will search everything linearly, then I will get to know page number 2 of process 3 is lying in frame number 5. Then I will go to frame number 5, and I will pick the data from main memory frame number 5. 

Searching time is the biggest problem. Due to searching time, the inverted page table was not a big hit. Because here we want to reduce the searching time, but the inverted page table has taken care of memory so that it doesn't utilize too much memory. Only to store page tables, we create one global page table. The operating system will maintain everything through it. But due to that, our searching time increased. And in normal paging, searching time is less, but memory use seems to be somewhere high.
