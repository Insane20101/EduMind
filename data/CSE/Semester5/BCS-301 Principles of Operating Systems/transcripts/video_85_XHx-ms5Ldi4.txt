Let's start with contiguous allocation. As the name suggests, we are allocating memory contiguously to the blocks of our file. This means that the storage we have, we are placing the data in a continuous way in the storage. There is a simple example: we often tell students to sit roll-number-wise in a class. Obviously, what happens there? Let's say roll number 1 sat on bench number 1, roll number 2 on bench number 2, roll number 3 on bench number 3, and roll number 4 on bench number 4. So, it is allocated in a contiguous way. 

Obviously, it is not necessary that roll number 1 must be sitting on bench number 1; wherever it starts, we will keep the next bench for the next roll number. This is the simple concept of contiguous allocation. Let me explain this with a simple example. Let's say we have 3 files, A, B, and C, in a directory. What is the actual use of a directory? Why do we use a directory? Because a directory contains all the information related to files. Here, I have taken only three pieces of information: the name of the file, where the file starts from, and what the length of the file is.

What we have done is, let's say we have File A. We divided File A into 3 parts, i.e., part 1, part 2, and part 3. Obviously, these become block 1, block 2, and block 3. This is the actual meaning of length. By length, we understand how many blocks it acquires in memory/storage, or how many physical blocks it will acquire. Similarly, we have File B, which we have divided into 5 parts, and File C, which we have divided into 4 parts. 

Why do we do this to data? It may be that the size of a sector is small and the file is very big. Because nowadays we are dealing with gigabytes of data and terabytes of data, the whole file in gigabytes won't be stored as it is. So we divide it, which is actually a logical division. The directory contains all this information.

Look at what we have done: we started File A from block number 0, or you can say from sector number 0. We have a disk. Usually, we make a disk with tracks and sectors, but here we have made it in a simple way. Now see, we have physical sectors inside the disk—the physical location where the data will come. We are starting from 0, meaning we are starting the first block of File A from 0. That means, from 0 to 3 of File A—the meaning of 3 is length 3. The meaning of length 3 is that the first is placed at 0, the second is placed on 1, and the third is placed on 2. 

So this is actually length 3. I have placed the first block at 0. Where will I place the second block? Obviously, the next location is 1. Where will I place the third block? Obviously, the next location is 2. That is the meaning of contiguous: you have to place it contiguously, not randomly anywhere.

Similarly, look at File B. We are starting File B from 6. Here is my sixth block. We have divided it into 5 blocks. So, starting from 6, we have 1, 2, 3, 4, 5. Look, we have stored File B from 6 to 10. Similarly, for File C, we are starting File C from 14 and dividing it into 4 blocks, which means physically it will take 4 blocks. Starting from 14: 1, 2, 3, 4. We placed the data contiguously like this. This is the simple meaning of contiguous allocation.

Now let's talk about the advantages and disadvantages, because a lot of questions are asked like this. They are of a very simple level, but many times, if you don't know the concept, you won't be able to visualize easily what is actually happening. 

The first advantage is that it is easy to implement. This method is easy to implement because we use pointers in other methods where we place data randomly, requiring us to use pointers, or in indexed allocation, where we have to make an extra index. Here, we are neither using pointers nor making an index. We simply state to start from 0 and put the data contiguously according to length.

Next is excellent read performance. This is a very important part. Whether we are doing sequential access or direct access, both methods are easy to access. Why? What is the reason for this? You know from this that if I have to read the data sequentially—let's say I have to read 6, 7, 8, 9, and 10—what actually happens in a disk? Let's say this is one track. In this track, let's say the 6th number is here. We enter the data in 6. The next block is on 7, the next on 8, the next on 9, and the next on 10, because we placed them from 6 to 10. We allocated these sectors contiguously. 

Now, when our read-write head reaches the particular track where the data is actually lying, it takes one seek time. What is seek time? It is the time taken to reach the desired track. Once it reaches the desired track, it has to do nothing simply except rotate the disk, and after rotating, you get all the data: 6, 7, 8, 9, and 10. If you had placed the data randomly—let's say you placed 6 here, the next block in another track, and the next in another track—then obviously you would have to change tracks again and again. As often as you change the track, the seek time will increase accordingly, and because of that, our access time will increase. So, in order not to increase access time, we placed the data sequentially. As soon as we reach the particular track, just rotate the disk and you will retrieve all the data. This read performance is excellent in the case of contiguous allocation.

The meaning of direct access is that, let's say, you want the 9th block. You don't have to access the whole file; you just have to access the 9th block of the file. It is easy in this case also, because you get to 6, and after that, you know obviously it is placed contiguously. It is like entering a class and knowing students are sitting contiguously. If you have to go to roll number 10, and you are standing at roll number 1, you know he must be sitting after 9 benches because roll number 1 is on bench number 1, roll number 2 on bench number 2, 3, 4, 5, etc. It is not like you have to search randomly. You reached one place, like you reached 6, and now you know that 9 must be 3 locations after it: 7, 8, 9. You will get 9 after three jumps. So, whether you do direct access or sequential access, or even if you access the whole file, your access time will be less, or you can say access speed will be faster. This is the main advantage of contiguous allocation.

Now let's talk about disadvantages. The first disadvantage is fragmentation. Fragmentation generally happens in two ways: internal fragmentation and external fragmentation. 

Internal fragmentation occurs when a physical block inside a disk—let's say its size is 5 KB, I am just taking a simple example—holds a file block whose size is 3 KB. When you enter 3 KB of data there, the 2 KB space remaining will not be utilized. Obviously, this is called internal fragmentation. There is no direct solution for internal fragmentation; it can occur everywhere. 

However, the major problem here is external fragmentation. While internal fragmentation happens when file sizes are low and there is nothing you can do about it, external fragmentation is quite popular in contiguous allocation. What is the meaning of external fragmentation? It has a simple meaning. Look: suppose you have placed blocks here—say you placed 1, 2, and 3, and you have also put this and that. Now you know you have, let's say, blocks 3, 4, and 5 empty. And let's say after that, this one is empty, and these three are empty. 

Now, suppose we don't have any more blocks after that. A new file enters, File D. File D wants, let's say, 4 blocks. It needs 4 blocks, meaning its total length is 4 blocks. Although you have a total of 6 empty blocks—1, 2, 3, 4, 5, 6—the problem is that these 6 blocks are not contiguous. First you have 3 empty, then there is data, then 1 is empty, then 2 are empty, and then there is data. What this means is that you have 6 blocks empty in total, and if a file demands 4 or 5 blocks, you should theoretically be able to place it, but you can't place them. The reason behind that is the requirement of contiguous allocation: you cannot place 3 blocks here and 1 block there out of the 4 blocks. It wants the 4 blocks collectively. 

This is called external fragmentation: you have available space overall, but you can't enter the data because it is not contiguous. This is a major disadvantage of contiguous allocation. This limitation is later removed by linked lists or index allocation, but it is the main drawback here.

Second, it is difficult to grow the file. As we already discussed, suppose File A enters and we place it in blocks 0, 1, and 2. After that, another file enters, File E, and we start it from block 3, giving it 3 blocks too. That means it is placed here easily. Now suppose File A (which was in 0, 1, and 2) demands some more space because we added something to it—like normally we make edits in files. We edited the file, and its size increased. Now, if the file size increased, I cannot provide space to the data. Why can't I do that? Because the next location is already full (filled by File E). 

However, space is available elsewhere, but it is not contiguous; it is far away somewhere. So I cannot grow the file now. I already mentioned that File A needs 3 blocks, File B needs 5 blocks, File C needs 4 blocks, but if they grow, it becomes difficult. If space is available contiguously right next to it, you can place it, but if the space isn't available there, it will not allow it to grow. If this were random allocation, then if you placed 3 blocks here and it demanded 1 more block, you could just say, "Okay, take this random block." But here you can't provide it because it needs data contiguously. 

Therefore, it becomes difficult to grow the file, to increase its size, or to edit and add something to it. And secondly, there is the issue of external fragmentation, along with internal fragmentation (though internal fragmentation is present in all cases and doesn't have any particular solution). Even if your file size is low, these are the constraints you face.

These are the major and important points related to contiguous allocation. Thank you.
