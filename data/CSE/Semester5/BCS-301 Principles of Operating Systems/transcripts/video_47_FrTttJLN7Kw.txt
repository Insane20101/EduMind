**Memory Management Techniques**

Operating Systems use various memory management methods to manage primary memory, that is RAM. As we know, the degree of multi-programming is very important. The degree of multi-programming refers to keeping more and more processes in the main memory, that is RAM, so that whenever the CPU needs a process to execute, whenever the CPU asks for a process to execute, we will have a plenty number of processes available in our RAM. Therefore, most processes will be available in the RAM when the degree of multi-programming is high. 

As we know, memory is a large area of bytes and every byte has some address. Now, what we are doing here is we divide the memory. Let's say we divide or partition the memory. Now, whatever number of processes come, my main motive is: what is the main motive of memory management? The maximum number of processes you have to keep in the RAM. This means we have to keep the maximum number of processes in the ready state. If the maximum number of processes are in the ready state, then definitely I will pick one of them and put it in the running state. Then again, if that process is blocked, or if for some reason it says that I want to perform an input-output operation, let's say that if I am writing a simple C code, in a simple C code if I write a simple program that I want to read the input from a file—let's say there is a file named XYZ, some xyz.txt file, and some content is written in this file, whatever the content, let's say some name is written. Now, whatever content is written in this file, let's say I want to print that data or print whatever is written in this content, I want to print that content on a monitor or, let's say, on a printer. Then, in this code, what will we write? We will write to read this file and then write it or print that content on the monitor. 

Now, when this program gets executed, when instructions are executed one by one, here we definitely use a system call, which is the read system call. So in the read system call, we generally write from where I have to read. We use the name of that file, the name of the file, and the size, which is a general thing, indicating up to where I have to read that content. When we mention the file name and where this file is located—this file is actually located on the hard disk—it means a running process, during the time the process was running, what is it saying in between? "I want to read this particular file." This is a simple example of an input-output operation. Many times we discuss that a process wants to perform an input-output operation, but what is the meaning of performing an input-output operation? It means that now it is reading a file from the hard disk, or accessing some printer, or accessing some monitor during execution. 

Then the CPU says, "Go and execute it." So when that process gets out of the range of the CPU, the CPU will sit idle. That is why we keep the degree of multi-programming high, so that whenever the CPU in any situation becomes idle, before that, we will allot another process from the ready state to the CPU. Therefore, the more processes are available with me in the ready state, the more my benefit, and the more I can utilize the CPU. And obviously, to make the degree of multi-programming high or to fill the ready state, I will have to properly utilize the RAM, that is, primary memory. 

Memory management techniques are all based on this. In memory management techniques, these are broadly of two types: contiguous and non-contiguous. In contiguous memory management, there is fixed partitioning and variable partitioning. Fixed partitioning is also called static partitioning, and variable partitioning is known as dynamic partitioning. 

To give a basic idea of the RAM, we will take each and every technique one by one, but here I am just giving a basic overview. What are we doing here basically? Let's say in my hard drive, these are my memory blocks—in the RAM, this is a general concept that we have divided the RAM into partitions or blocks. Let's say a process P1 comes. What we do here is we adjust the entire P1 process in a particular block, meaning the entire process goes into some block, a memory block. Which memory is this? That is the RAM, the main memory. And all the blocks of the main memory, meaning the full capacity of the main memory—we cannot use the full capacity because when we switch on the system, the operating system first of all is loaded into the main memory. The operating system covers some area of the main memory, and in the remaining portion, what we do is we try to fit the maximum number of processes into it so that my degree of multi-programming becomes high. 

Contiguous memory management, as we can know by the name, means continuous allocation. This means whatever number of similar kinds of processes come, we will provide them a continuous amount of memory. Let's say there is a process, and that process has four blocks, let's say B1, B2, B3, B4. So what we basically do is give them continuous memory allocation, providing them continuous addresses. If, let's say, process P1 comes, I allocate P1 here. The next process P2 comes, so we try to keep it in continuous addresses. That is the simple meaning of contiguous allocation. 

And in this, we use two things: fixed partitioning and dynamic partitioning or variable partitioning. This means we can either fixed-divide the memory, making slots of a particular size, or we will not make any slots. When a process comes, if a process comes and says that it wants 1MB, then I will dynamically allocate 1MB at runtime in the RAM. This has some advantages and some disadvantages, which will be discussed in further videos. 

Fixed partitioning and dynamic partitioning—if I talk about fixed partitioning, then it was used long back, meaning roughly in the 1960s, we used to use it in mainframes. When mainframes were very big servers, we used it there. So it is not very important from the GATE point of view, but from a foundational point of view, it is important. And what is its second importance? Nowadays we are using advanced techniques. We have reached up to this modern technique here, but where is the base of that technique made from? From these older techniques. The techniques that were used at that time, what were the problems in them? To remove those problems, we kept doing further evolution. That is why their importance remains. 

Similarly, non-contiguous allocation—non-contiguous means, as we know from the name, we are not doing continuous allocation; we are doing non-continuous allocation. What do we generally do in this? If there is a process, let's say a process can be stored or can be put in different locations of the memory. We are not putting it continuously. Let's say there is a process P. First, what we do is we divide the process; we divide the process into different blocks, and we do partitioning. Let's say there are four partitions of this process. There is a process, and there are four partitions of that process: P1, P2, P3, P4. And now the memory block—this is the memory block in the RAM. 

As we know, some portion is occupied by the operating system. Now, let's say that one of the partitions has P1. In continuous allocation, the next partition—let's say this address, let's say addresses 0 to 20 are taken by the operating system, so 21 to, let's say, 40 is taken by partition P1. What will happen in contiguous allocation? The next partitions P2, P3, and P4 would be continuously allocated so that when we search for one process, when the CPU says that I want to search for this instruction in that process, my searching will get fast somewhere, because I know that my process will start from, let's say, 20. Let's give some addresses: 60, 80, 100, 120. 

So what we will do in contiguous allocation is put P1 partitioning here, then P2, P3, P4—meaning continuously allocate them. But in non-contiguous allocation, if P1 is here, then P2 can possibly be at some other location. It is possible that some address is already occupied, and then let's say P3 comes here, and P4 comes here. This area is already occupied by some other process, you can say it is already occupied by another process. This is possible because we are not saying that only one process can come at one time. At one time, different partitions of many processes can come; their continuous allocation will not happen, and discontinuous allocation will happen. Anywhere we can put it, separated at any location. That is the concept of non-contiguous allocation. 

So let's say we put P1 here, some other process's partition is here, we put P3 here, P4, P2, and similarly, some other process's partitions also come in between. That is non-contiguous allocation. And in this, the major techniques we use are Paging, Multilevel Paging, Inverted Paging, Segmentation, and Segmented Paging. 

So about these, one by one, we will see fixed partitioning and variable partitioning. This is all about the different techniques of memory management.
