Transport layer is the 4th layer in the OSI model, which takes the data from the application layer and passes it to the network layer. This means it takes data from the application layer/user and passes it on to the network layer. 

Now let's talk about the responsibilities of the transport layer here. What is the role of the transport layer and what are its functionalities? The first and very important role of the transport layer is end-to-end delivery of the data. Now what is end-to-end delivery? End-to-end delivery is also known as port-to-port delivery, meaning they do end-to-end delivery by using port-to-port delivery. What is port-to-port delivery? Let's say there is some network A in which there are a lot of hosts. I have different hosts which are connected by some topology. Let's take one more network B; there is another topology in that network also, and devices are connected among themselves. Now in this network A, A1 wants to communicate with B1. If A1 wants to communicate with B1, then first of all, let's look at the data link layer. The responsibility of the data link layer is that when a message is sent by A1, then to which node will it go first? What is the first node where the message will reach first? Then from that node, which is the next node it will go to? Then from that node, which is the next node it will go to? This means node-to-node, hop-to-hop delivery. 

The responsibility of the network layer is that this A1, meaning this machine—the machine which is called as a host also, this can be a server, a laptop, a mobile phone, or any other device, there is a machine—the responsibility of the network layer is to carry the message from this machine to that machine. But the transport layer is working above that; it is above the network layer, and its responsibility is end-to-end delivery or port-to-port delivery. Now what is port-to-port? The A1 machine we have, it may be possible that multiple applications are running in the A1 machine, like in my laptop, I'm working on a web browser, and multiple tabs are opened there. Among them, from which tab, meaning among different applications, which application is transferring the data? Now every application has its own port number here. We will discuss further about port numbers. A port number is basically a number of 16 bits. Among them, some are well-defined port numbers, and some are registered port numbers. Like SMTP, meaning if I'm sending a mail from my system, I'm sending a simple mail through Gmail, then Gmail uses the SMTP protocol on the back-end—Simple Mail Transfer Protocol—and the port number of that Simple Mail Transfer Protocol is 25. That means whenever data will be sent from my machine, from that machine data is going through which application? Through port number 25. And when that data will reach on B1, it reached on that machine, server, laptop, wherever the message will reach, it may be possible multiple applications are running on that machine also. From the multiple applications, my message should reach which application further? For that, we use the transport layer, and that is executed actually by using port-to-port delivery. This means the message was sent by the 25-number port of my machine. Let's say there's an application in B1 and let's say its port number is 120—I'm just taking a normal port number, let's say its port number is 120—the message should reach on that application only, not like all the applications are receiving that message. For that, we use the transport layer. So the actual meaning of port-to-port delivery/end-to-end delivery is that from where the message is sent from our machine and on the other machine it is received on which application. That is called end-to-end because the end thing in my machine is a process/program. Delivering a message from my process to another process is the responsibility of the transport layer. That's why it is called end-to-end/port-to-port delivery/process-to-process delivery. 

Another responsibility of the transport layer is protocols. The transport layer uses two majorly used protocols, other than HTTP and a lot of further protocols, but the most importantly used protocols are TCP and UDP—Transmission Control Protocol and User Datagram Protocol. Now if I'm using TCP, what is the advantage here? If I talk about the network layer, we discussed in the network layer about the IP protocol. Now whenever we send a message on this IP protocol or network layer protocol, that message is unreliable. This means I'm sending that message without any guarantee. But if I want to send that message with proper guarantee, meaning if I want to achieve reliability there, then I'll send that message through TCP. TCP provides reliability here. 

What does reliability include? That if I have sent any 4 messages or packets, then the receiver is also receiving 4 packets. And secondly, other than this, it follows in-order delivery of the message. In-order means, let's say, I sent message A, B, C, D. First I sent A, then B, then C, then D, then the receiver should also receive first A, then B, then C, and then D. This is called in-order delivery. Like, in our laptop or system, when we press buttons on the keyboard—let's say I pressed something, let's say, live. L-I-V-E. First I pressed L, then I, then V, then E. Now when this message will be printed on the monitor, then it should be printed as LIVE. It means to say that we're talking about in-order delivery: the order in which I pressed the buttons, the printer or monitor showed it in the same order. That is called in-order delivery, live. Now if there's any mistake, let's say it receives some out-of-order packet instead of live, then it may be possible it prints evil: E came first, then V, then I, then L. So its meaning is changed completely. So that's why I need in-order delivery of packets here. 

And secondly, there shouldn't be loss of data. Loss of data should not be there, meaning if I'm sending 4 packets, 1 or 2 packets are missing in between, firstly the receiver should know that some packets are missing, and secondly, each and every packet should be received there. This is the responsibility of the transport layer. And if you're using TCP, then TCP is connection-oriented. Connection-oriented means it makes a connection before sending the message, like your telephone, meaning you'll start talking afterwards, but first there will be connection, connection orientation. After connection orientation, there is a dial tone. A dial tone is a kind of connection orientation. After all that, you will start to talk. But the network layer in some way is like the old postal services, like we used to send letters. What happened in that is that it may be possible many times that I wrote a letter, it may be possible my letter doesn't reach the destination, there's some loss, or maybe the message will be received out of order. But if I want reliability there, in-order without data loss, for that I can use TCP. That is the advantage of the transport layer. If I don't need reliability, then normally I can use UDP. So if on your application layer, like we send web pages through HTTP, if we're sending web pages through HTTP and if I need reliability there, then I'll use TCP for sure because it works on connection orientation. 

Then the third responsibility of the transport layer is error control. It does error control by checksum, and error control is also done by TCP. In TCP, we basically use the checksum method. Checksum helps in detecting errors, and it's best if we can correct it, but at least if we detect the error, that is also a very important part. Now the errors, we discussed that we try to detect errors in the data link layer also, but there we use CRC, and we use the checksum method here. And this error control is done end-to-end, meaning when this message will be sent, when B1 will receive this message, then by using checksum at its own end, B1 will try to match that the checksum sent by the user is matching with the checksum of B1 or not. Meaning B1 will calculate the checksum of that data again; if that checksum matches, that means there's no error. If that checksum doesn't match, then there is an error. But in the data link layer, every node tries to detect errors, so that's why here we control errors by using the checksum. 

Another functionality and responsibility of the transport layer is congestion control as well as flow control. We have the same methods in flow control: stop-and-wait, go-back-N, and selective repeat. Flow control means at what speed the sender is sending messages to the receiver and of what size. For this, we use the advertising window method here, meaning the receiver already sends its window to the sender, stating that this is the size of my window. So whatever messages you're sending, those messages should be according to the window. A window is what? A kind of capacity. Meaning the receiver already told its capacity to the sender, stating to send me messages of this size and this number of messages. It will inform about both: first the size of the message, and then how many messages of that size. When both things will be known, then the sender will send the message accordingly. From that, my flow will be controlled. But if there wasn't flow control, there can be congestion in the network. If there's congestion on the network or on the server/machine/receiver, then the transport layer tries to remove or avoid that congestion also. There is a method like AIMD (Additive Increase Multiplicative Decrease); that is a method which is used to do congestion control. We will take all the algorithms one by one in detail. In this video, we're just talking about the functionality or roles, and what the roles of the transport layer are here. 

After congestion control and flow control, in the transport layer, we use the terminology segment. This is called segmentation. Meaning when data comes from the application layer, then that data doesn't have any defined length. Data comes in continuous streams; this is called streaming, meaning continuous bits are coming: 01, 01, 01, 01. And I can't send those bits further directly. I have to put them in proper segments, where I have to set a header along with that there will be data. So what are TCP and UDP doing there? Whatever message is coming there from above, they are sending those messages to the network layer by dividing them into segments, because the message coming from above is continuous, the bits are coming continuously. They will pick up those bits, put them in a segment, and then send it down. Then more bits will come, they put them in a segment, and it will keep sending it to the network layer by making segments. That is called segmentation. 

One more responsibility of the transport layer is multiplexing and de-multiplexing. Multiplexing and de-multiplexing mean whenever the data comes from the application layer—meaning a lot of protocols/applications are running on the application layer, multiple tabs are opened on my laptop, multiple applications are running, and it may be possible that some applications from those multiple applications are sending their data, let's say 4-5 applications are there: A1, A2, A3, A4, A5, and all these applications are sending data—then the transport layer doesn't make specific connections for all. Meaning, in our laptop, there's only one connection; we're connected to the whole internet. So whenever multiple applications send data/messages, then the transport layer works by multiplexing it (i.e., many-to-one). It sends that to the channel, meaning the media/channel we're using, and data from multiple applications comes and that data is sent to the channel. And on the back-end, meaning what will happen at the receiver, at the receiver messages are coming continuously, but it may be possible some messages are for some application, some are for some further applications, and some messages are for different applications, meaning at the end of the receiver, it is working as de-multiplexing, which is a one-to-many function. Because multiple messages are coming, a lot of messages are coming from one channel, but a message, for example, is for Gmail, another message is of some other application, another message is of some third application, so sending those messages to the appropriate applications, that is also the responsibility of the transport layer, and we call this multiplexing and de-multiplexing.
