### What is a Firewall?
A firewall is a device—meaning you can implement it as hardware, software, or a mixture of both hardware and software. It is a device that monitors and controls incoming and outgoing traffic based on defined rules. We provide it with predefined rules, and on the basis of these rules, it checks incoming and outgoing packets. It keeps complete monitoring over them and controls them, which means deciding whether to pass or deny them.

### The Barrier Analogy
Like in metro stations where security personnel check all the bags, you can think of a firewall as scanning all the packets in a similar way. It acts like a barrier. For a simple example, if we talk about your college or university, what is the boundary? Anyone cannot just enter from anywhere in your university or college. They have one or two gates for entry—maybe more, but the others are closed. With only one or two main gates, any authorized or unauthorized person must enter through those specific gates. We put a security system there inside our organization, company, or college. We do not allow unauthorized people to enter because once they enter, they can definitely cause harm to our system. Therefore, we have to stop them at the gate. In general, we implement a firewall at the main gate of our organization so that a person or packet can be stopped and scanned right there before entering.

### Host-Based vs. Network-Based Firewalls
Next, we have host-based and network-based firewalls. Generally, a host-based firewall is located inside the machine. If you are using the Windows operating system, you will find the complete settings for firewalls inside your laptop. This generally comes under software, meaning the software running on that machine acts as a firewall. 

However, at a larger level in a company or organization, we generally use a network-based firewall. This scans the whole network, and we use dedicated hardware for it. In your laptop, the system is not only running a firewall; it is doing all other kinds of work while also running the firewall software. In a company, a network-based firewall will have dedicated hardware, and the firewall software will run on top of that dedicated hardware. If there is no such mandate, you can also implement a firewall on a normal server that is already doing other work. However, if you want full performance, you should install a dedicated hardware server for the firewall. This will perform much better because there are no shared resources.

### Trusted vs. Untrusted Networks
Let us explain this with a diagram. Here, we have the internal network. Your company's or organization's private network is what we call the "trusted" network. It is trusted because you have hired employees, workers, or trainees who are properly authenticated. On the other hand, the external network—the public network or the internet—is full of threats and vulnerabilities. When a request comes from there, we may know the IP address, but we do not know who is actually sending the request. They might be sending it from Malaysia, or they might be trying to launch a denial-of-service attack. Any attack is possible. Therefore, whatever packet or request is coming from the outside should not enter our system directly, just like someone cannot enter a college or university directly. It must enter through the firewall, which will check it first. This is our main motive.

### Categories of Firewalls
In firewalls, we generally have two categories: Packet Filtering Firewalls and Application (or Proxy) Firewalls.

### Packet Filtering Firewalls (Layer 3 & Layer 4)
If we talk about packet filtering, we generally call it a "Layer 4" firewall. You may have also heard of Layer 3 firewalls. A Layer 3 firewall works on three layers of the TCP/IP model: the physical layer, the data link layer, and the network layer. Obviously, a Layer 3 firewall works up to the network layer, meaning it checks the IP address. 

However, a packet filtering firewall that works at Layer 4 performs better. It works across the physical layer, data link layer, network layer, and up to the transport layer. It checks the IP header and the TCP header of whatever packets are coming to us. Every packet definitely has an IP header and a TCP header. The firewall checks the entries of these headers. Generally, it checks the IP address and the port number. In the IP header, the most important thing is the IP address, and in the TCP header, the most important thing is the port number. It checks both of them properly. Working inside the network and transport layers, it can block an IP address, meaning we can block a specific IP address so that any packet coming from it cannot enter. We can also block an entire network, meaning we will not receive any packets from that network. We can also block specific services.

### Predefined Rules and the Default Allow Policy
If we look at the diagram, we have predefined rules. These rules define what is denied (not allowed) and what is allowed. In general, we call this a "Default Allow" policy. This means we allow everything by default, except for the specific rules we have mentioned in the table, which we do not allow. This is a better approach when we want to stop specific targets; we list them and allow everyone else. 

For example, let's look at our internal network. Let's say the internal network is working on the IP address 172.9.0.0, which is a Class B network. Within the organization, we have created our own intranet. The whole world knows us by this address, 172.9.0.0. Usually, we use domain names, but we are not talking about DNS here; we are talking about the IP address of the entire domain.

#### Rule 1: Blocking a Specific IP Address
Now, let's talk about the first rule. Look carefully at the first rule: if any packet arrives at the firewall and the source IP of that packet is 179.24.8.0, it means a packet has arrived from the outside public network. This IP address can be from anywhere in the world. What we did with this specific IP address is block it. If any packet comes with this IP address, it will not be allowed to enter; the firewall will drop it here.

#### Rule 2: Blocking an Entire Network
For the second rule, we have 152.32.0.0, which is a Class B network. You can take any network. Here, we have blocked the entire network. In the first rule, only one IP address (one person) was blocked from accessing. Here, we blocked the entire network, meaning no one from that entire network can get access. As a simple analogy, it is like blocking an entire city from entering the college or university. If any IP address comes from that network—such as 152.32.0.1, 152.32.2.3, or 152.32.2.4—any address starting with 152.32 will not be allowed because we have blocked the entire network.

#### Rule 3: Blocking a Service (Port 80 / HTTP)
Then we have the third rule. The source IP is listed as "any," meaning whatever the IP address is, it does not matter. However, the source port is specified as 80. Port number 80 is for HTTP services, which means web pages. If you access web pages, you do so through HTTP requests. If a packet is going out of our internal network and the firewall sees that the source port is 80, it means someone is sending an HTTP request. If we want to prevent anyone from the outside world from accessing our web pages, we can block it. Likewise, if a request is coming from the outside and its source port is 80, meaning they are trying to access our web services, we can simply block port 80. This is how we can block services. Along with IP addresses and networks, we can block entire services like HTTP, FTP, or Telnet using a packet filtering firewall.

#### Rule 4: Blocking a Destination IP
Next, we have the fourth rule. The source is "any," and the destination IP is 172.9.0.3. If a packet comes from the outside, its destination IP is 172.9.0.3, which belongs to a host inside our internal network. We are saying that this host cannot be accessed. We might have blocked a specific destination IP because we have a mail server running on that host that contains confidential data, or we have hosted an app there that we do not want outsiders to access. So, we block access to that destination IP.

#### Rule 5: Blocking FTP (Port 21)
Lastly, look at the fifth rule. The source is "any," but the destination port is 21. Port 21 is the destination port for FTP requests. If any person outside our internal network sends an FTP request to transfer files, we block it. Why do we block it? FTP services have vulnerabilities and a lot of authentication problems. That is why, in general, we keep FTP closed so that unauthorized persons cannot access it. 

In this way, we can block services, specific IP addresses, and entire networks. This is what we do inside a packet filtering firewall.
