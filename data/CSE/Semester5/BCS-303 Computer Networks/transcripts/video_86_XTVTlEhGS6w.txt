### What is Socket Programming?
Socket programming is a way for applications to communicate with each other over the internet. It defines how applications communicate and transfer data with each other over the network. 

A socket is a node or an endpoint. This means that data generated by an application in the application layer of one node will be sent to the application layer of another node. A socket is an endpoint, which can be a node, a machine, or any similar entity. 

I will explain these system calls and how communication is actually done using a real-life example. You are often asked about this, so this explanation will help you answer easily and remember it always. 

### Server and Client Flowcharts
The flowchart of the server consists of commands and flows on one side: first `socket`, then `bind`, `listen`, and `accept`. The flow on the other side is for the client machine, which starts with `socket` and then `connect`.

First, let us talk about the server and the client. There is a socket on the server and a socket on the client. The `socket` is the first system call, and its purpose is to activate the endpoint, meaning it activates the machine or node. 

### The Socket System Call and Parameters
There are three parameters in the socket system call:
1. **Domain**: We specify whether we are using an IPv4 or IPv6 network.
2. **Type**: We specify whether we are using a datagram service or a stream service—meaning, whether we are using TCP or UDP. If we are using TCP, we mention it as `SOCK_STREAM`. If we are using the datagram service (UDP), we mention it as `SOCK_DGRAM`. 
3. **Protocol**: In the case of IP, we mention the value of the protocol as `0`. 

This covers the number, type, and domain of the protocol. This is the first step, and it is the same for both the client and the server. You are initializing the endpoint and the machine first.

To explain this with a real-life example, imagine two telephones. If we talk about a landline network, we can take the example of a Public Switched Telephone Network (PSTN). These are your two endpoints: one telephone and the other telephone. You can think of the socket step as installing the telephones first in your house and in your friend's house. At this stage, your sockets and endpoints are ready, but communication has not started yet.

### The Bind System Call
The next step for the server is binding. Binding means associating an address. From a telephone point of view, this is like associating a telephone number to the physical box you just brought. 

In socket programming, you are assigning a socket address to the server. A socket address is a combination of an IP address and a port number. If you are using IPv4, it has a 32-bit logical address, plus a 16-bit port number. Thus, you are assigning a 48-bit socket address to the server. In our real-life example, binding means giving an address to these telephone numbers so they are bound to the devices.

### The Listen System Call
Next comes the `listen` system call. Once the number is assigned, the server goes into passive mode. The server waits in passive mode for a client connection. In our telephone analogy, this is like when the phone is waiting for a call. The server is waiting here through the `listen` command for an incoming request.

An important parameter here is the backlog. The backlog is a queue, and we specify the length of this queue. In this queue, we store pending requests from multiple clients. If the queue becomes completely full, we send a message to the client indicating that the queue is full, the connection cannot be established right now, and they should try again after some time.

### The Accept and Connect System Calls
Then, the server will accept requests from that queue. Accepting means picking up the call. While waiting for the call is the "listen" phase, when the call actually arrives, you pick up the receiver and start talking. This is the core process on the server side.

Now let us talk about the client. I have already explained the socket step for the client. After the socket, the next step is `connect`. Connect means dialing the number. You pick up the receiver and dial the number; that is what the `connect` system call does. In the `connect` call, you provide the socket address (IP address and port number) of the server. This allows the server to listen to the request, place it in its queue, and then accept it.

### Data Transfer and Connection Termination
Once the server accepts the request, communication starts. In TCP, this is where the three-way handshake completes and the connection is established. After the connection is established—meaning the client dialed the number, and the server picked up and accepted the call—the communication between the two begins.

To communicate, we use `send` and `receive` system calls. First, one party speaks (sends) and the other listens (receives), and then the roles reverse. This two-way communication continues. The `send` call works like a `write` system call, and the `receive` call works like a `read` system call.

When the communication is complete, the user hangs up the call, which corresponds to the `close` system call. After closing, the connection is terminated. You can establish the connection again later, but this is how all these socket programming commands are used. You may be asked questions related to this process.
