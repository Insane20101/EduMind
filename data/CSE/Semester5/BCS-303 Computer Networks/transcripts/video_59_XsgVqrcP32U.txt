Now, what is its use? Why are we using IPsec? 

Its first use is **confidentiality**. Whenever we talk about how no one should read our data in the path—because the internet we are using is full of threats, there are many loopholes and vulnerabilities, and anyone can attack the message or the channel in the path and can acquire the message—what we try to ensure is that if there is an unauthorized person in the way (like A sending a message to B, if there is someone in the way who is unauthorized), we want that person not to be able to read the message, they can't read that. It is called confidentiality. We call this as privacy also. For that, we use encryption. We need a protocol that provides encryption, and this is defined in IPsec. 

The second feature is **authentication or integrity**. What does authentication and integrity mean? It is also of two types: one is the authentication or integrity of the message, and the other is of the source. 

If I talk about the message: if A sent some message to B, and someone changed it in the way—some unauthorized person changed it—and when that message was received by B, then B didn't know that it was changed. It will be messed up like this. At least B should know that the message is changed, and that some wrong modification has been made. Checking that is actually checking the integrity of the message, or checking the authentication of the message. We use hashing for this, but the same thing is defined in IPsec. 

Similarly, consider the source: A sent a message to B. B is happy. But if someone else sends a message as A by using the IP address of A, and it sends a message to B, then it should be authenticated. B should know if it is the real A or if someone is pretending to be A. So the authentication of the source is also important, and for that also we use IPsec. It provides this as well.

The third feature is **replay attack protection**. This means when A sends some message to B, someone acquires this message in the path, and it is sending that message again and again after making some changes. "Replay" means it is sending that message repeatedly. 

Let's say, if a message is sent to B saying "send 1000 rupees in my account," it is done. B thinks that A has sent that message, so it sends 1000 rupees (replay happened there). After some time, again that message appeared: "send me 1000 more, send me 1000 more, send me 1000 more." The same message is sent repeatedly, so there may be a chance that B thinks it is genuine. And if it happens, B will be in a loss. Meaning, if these messages are replayed continuously, that is what a replay attack is. We use IPsec to give protection from this replay attack. 

You can use all of these features, or you can use only one of them. If someone says that I want this only—I want only authentication, or integrity, or just confidentiality—so you can use just a particular one also, or you can use the entire collection.
