First of all, as the name suggests, Ring, Token Ring. So this uses which topology? It uses Ring topology. Why is this important? Because in IEEE 802.3, we discussed Ethernet, in which bus topology is used. And if we talk about the Data Link layer, the standard protocols in the Data Link layer like Ethernet (IEEE 802.3) or IEEE 802.5, exams often ask about the differences and which topology they use, so you should know these points. Thus, Ring topology is used here.

The second point here is which access control method we use: Token Passing. What does this mean? If we talk about ring topology or Token Ring, how will you make its diagram? These are different stations, and these stations are connected in this way through a ring topology. There are multiple stations; we can give them names like A, B, C, and D. Now look, here A, B, C, and D are all connected by a ring topology. But which device will do transmission when, and which device will not do transmission now? How will we know about this? Because if all do transmission at a time, then there will be a collision. 

So which device will access first, who will access the media first, and how to decide this? For this, we use the concept of token passing. What happens here is that a token is revolving—meaning it is moving. The station that is ready with data will capture the token, hold it, and then start the transmission of data. And when its transmission is complete, it will release the token. This is a simple concept. 

Then similarly, the token will again keep revolving. The station that is ready will capture the token before sending the data, and then start transmitting data. No one else can send data at this time because they do not have the token. Only the station that has the token can transmit the data. This simple concept is used here.

Next, regarding whether Token Ring is bidirectional or unidirectional: it is unidirectional, meaning you can use it in simplex mode. Whether you take clockwise or anticlockwise, the movement will be in one direction only, and data will move only in one direction.

If we talk about the data rate, the data rate we use here is 4 Mbps and 16 Mbps. Earlier these were used, and now slowly many variations have come out, so multiple rates can exist, but if you are asked by default, you can say 4 Mbps and 16 Mbps. What is the data rate? It is what we also call bandwidth—how many bits of data we can transmit per second.

Regarding the token, it also has to be released. Once you capture the token and start data transmission, you transmit the data and send it. Now you will release the token. There are two concepts of releasing the token: early token release or delayed token release. Early means that as soon as you send all packets and all messages, you release the token immediately. In delayed token release, what happens is that you transmit the first packet, then the second packet, and when that packet goes around the ring and returns to you, you know that your packet has traveled the whole ring. Only then will you release the token. There are some numericals on this, but they usually come in GATE or UGC-NET exams, though they are not asked in normal exams. Still, in the next video, we will have a discussion on that.

If we talk about acknowledgement, the concept of acknowledgement is not mentioned clear-cut anywhere regarding whether acknowledgement is used in Token Ring or not. But if it still comes up anywhere, you can use the concept of piggybacking acknowledgement. This means you can say yes, acknowledgement is there, but via piggybacking. What does piggybacking mean? You send the acknowledgement along with the data so that traffic is less. Sending the acknowledgement separately and the data separately is less efficient than sending the data and an acknowledgement along with it, so that the number of packet transmissions is reduced and the load or traffic on the network is minimized. That is why we use piggybacking.

Next, Differential Manchester Coding is used. While there are multiple coding techniques like NRZ, Differential Manchester, and Manchester Single, here we use Differential Manchester Coding. Next, we have a monitor. Here, we use a monitor station. What is the purpose of the monitor station? Many times, what happens is that a packet or frame is moving around the ring and becomes corrupt. Because it is corrupt, no one is accepting it, so that frame becomes a stray packet and keeps moving around while no one accepts it, creating unnecessary traffic. What do we have to do? We have to remove these types of packets. There are other things we have to monitor as well. For that, one station here works as a monitor. If we talk about the frame format, here we use two frame formats: one for data, which is the data frame format, and one for the token. Here, I am just giving you a basic introduction, but in further videos, we will cover this in detail because it is difficult to cover everything in one video.

First, talking about the data frame, it includes:
* **Start Delimiter:** 1 byte. All these values are in bytes; remember they are in bytes. Start delimiter means the packet starts from here, and we use it for alerts and synchronization.
* **Access Control:** 1 byte. Used to decide priority, reserve bits, and check if the token is present or not.
* **Frame Control:** 1 byte. Used to determine if the packet/frame you are sending is a data frame or a control frame, because many times we have to send control frames rather than data.
* **Destination Address and Source Address:** 6 bytes each, because we are working with MAC addresses here. As you know, a MAC address is 48 bits, which you can say is 6 bytes.
* **Data:** The size of the data depends; minimum you can send is 0 bytes. How much maximum can you send? It depends on the token holding time—how long you can hold the token determines how much maximum data you can send. This is an advantage compared to Ethernet, where the maximum size is fixed (like 1500 bytes) and cannot be exceeded. Here, you have an advantage compared to Ethernet.
* **CRC (Cyclic Redundancy Check):** 4 bytes, used for error control.
* **End Delimiter:** 1 byte, marking the end of the frame just like the start delimiter marks the beginning.
* **Frame Status:** 1 byte. I will tell you about this in detail later.

Finally, talking about the token, the format of the token is 3 bytes. It uses the Start Delimiter, Access Control, and End Delimiter fields. We will discuss these in detail in the next video. Thank you.
