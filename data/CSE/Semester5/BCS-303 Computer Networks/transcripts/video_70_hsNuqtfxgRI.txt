After that is header length. Header length is for 4-bit numbers. 4-bit means, let's say I have a number 1000. Now what is 1000? 1000 is 8, meaning my header is of 8 bytes. Meaning if there are 4 bits of header length, in 4 bits the maximum number could be 1111. What is 1111? It is 15. Meaning the receiver is sending the sender the acknowledgement by using flag 1 as well as sending the acknowledgement number, but this number will be written over here. 

Then Push. Push is PSH, meaning if the sender is sending some data to the receiver—here it happens many times that there is a minimum segment size that I have to send this size of segment. But many times when we use interactive applications like chatting, we don't send big data; we send 1-1 bits, like hi, hello. So when we are sending data of 1-1 bits or bytes, it happens that the receiver continuously stores the data in its buffer. Meaning one byte came first, then 2 bytes came; the receiver has stored that data in its buffer, but it will give it to the application layer after some time when the buffer will be full. It thinks that let all the data come first, I will send the data in a bundle. But sometimes push happens here. Push means that I want the buffer not to be filled completely; if I'm sending one byte, then that one byte should be sent to the receiver quickly, and the receiver's application should accept that. 

Meaning, generally when we go to courier something, I went to courier something at 9 o'clock in the morning. But there can be some couriers which are very important; I want that data to be sent immediately. In that case, I will not wait for 12 o'clock. If I am sending the data at 9 o'clock, I will tell the courier person to push that immediately. So that is the advantage of the push. So if the bit is 1, it will get to know that you don't have to keep the data in the buffer; send that to the application layer immediately.

SYN flag. SYN flag is used for synchronization. Synchronization means when we send the data, when we make a connection, the first packet will always be a SYN flag. Next is the window size. What is the window size? 16-bit. 16 bits means 65535, meaning 0 to 65535. So whatever amount of segment I want to send, I am using this window size, basically for the receiving window. Receiving window means when the sender sends the data, it advertises its window also so that when you will send the data, that data shouldn't be more than that. Meaning every sender sends its window along with the data; it tells its capacity, that "this is my capacity." And when the receiver will send data, it will also tell its window, that "this is my capacity, so send the data accordingly." 

Because TCP is working as full duplex, when A is making a connection with B, then A will advertise the size of its window in it. Meaning let's say the size of my window is 10000, then it will send 10000 written in that. So B will get to know that A won't accept data more than 10000. When B will send data to A, then it will also advertise its window, let's say 20000. So when A will receive this packet, A will get to know that the capacity of B is 20000. So they tell their capacities by writing it in the window size, and by using window size, they manage flow control. 

Checksum. Checksum is 16 bits, which is used for error control. When we talk about pseudo-checksums, we will see this in detail, but the advantage of checksum here is that this helps in error control. In the data link layer, we use CRC, and in the transport layer, we use checksum.

So this MSS means in my network, every network has its own MSS, its own segment size. So generally whenever A and B, any two entities, will communicate with each other, they send their MSS (maximum segment size) in the options. 

If I talk about window size, window size is the total capacity. Meaning let's say window size is written as 10000; in total, I can accept 10000 bytes. But let's say if the MSS is of 1000 bytes, meaning the size of one segment should be 1000, meaning indirectly I am saying that you can send 10 segments of 1000 so that my capacity of 10000 bytes gets completed. So if the window size is 10000, it doesn't mean it is the MSS. Often students get confused between window size and MSS. Window size means my total capacity is 10000, but I can accept one packet of 1000; if you send me 10 packets of 1000 bytes, then my capacity will be properly fulfilled. So this is the MSS value which we generally send in the options and padding.
