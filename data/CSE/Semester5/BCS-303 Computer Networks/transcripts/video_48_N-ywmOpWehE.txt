Hello friends, welcome to Gate Smashers. The topic is Classless Addressing. The concept of Classless Addressing came in 1993 after the concept of Classful Addressing. In Classful Addressing, we divide the IP addresses into 5 classes. Because of that, there is a problem of flexibility, and what other problems or disadvantages occur in Classful Addressing—for that, you can follow my video, and in this video, we are going to discuss only the concept of Classless Addressing. 

Let's start Classless Addressing. First of all, the first point is no classes, meaning here you forget about Class A, B, C, D. There is no funda of classes here. Here the concept is of blocks. Block means, if a user says to me that I want $x$ amount of IP addresses, then I provide him $x$ amount of IP addresses. Meaning, whatever is the user's demand, that size of block I provide the user. 

But in Classful Addressing, there's nothing for the user. A user says that I want, let's say, 1000 IP addresses, but there is no funda of 1000 IP addresses there. Maybe, if I give a Class A address, in Class A there are 1 crore addresses in my network. So the user has demanded only 1000, but I can't fulfill his demand as-is if I am following Classful Addressing. So in Classless Addressing, wastage of IP addresses is very less because whatever the user's demand is, a block of that size (block means how many IP addresses he wants) I will provide him with only those many IP addresses, because it is handled by IANA (Internet Assigned Numbers Authority). The block size that the user demands will be provided to him.

Now, what does "block" mean here? One is the Block ID and another is the Host ID. Meaning, there we had Network ID and Host ID; here we are talking about a block. So block address here—talking about IPv4—in IPv4, an IP address is of 32 bits, but now the MSB bits in it represent what? Block ID. Meaning the block, we are talking about the network (you can take network instead of block, but it is not fixed as in Classful). And other bits represent what? How many hosts are there in that block—that is what it is representing. We will see with an example.

Next is the notation, which is a very important point. The notation in Classless Addressing is `x.y.z.w`, meaning the same: I have 4 octets, 1 octet for $x$, $y$, $z$, and $w$. But the new thing is `/n`. What does `/n` notation mean here? Here $n$ represents mask; you can call this mask, or the number of bits representing the block or network. What is the funda of $n$ here? Otherwise, if an IP address is given to me, how will I know how many hosts are there, or what is the Network ID? So to tell me this, `/n` will help, because here $n$ is working as a mask. Mask means continuous 1s. The number of 1s is represented by `/n`, which we can say in other terms is the number of bits used to represent the Network ID part, or Block ID part—that is what $n$ is. 

We'll see an example. Let's say `200.10.20.40/28`. Now you know that this is a normal IP address which you have seen before. What is a new thing here? `/28`. Now what is the concept of `/28` here? There are 28 numbers of 1s. Meaning the Network ID part is represented by 28 numbers of bits. So how much is the Host ID part? If I say this is a 32-bit IP address, then what is this 28? That is the network part. So what is remaining? 32 minus 28, that is 4, because 28 and 4 is 32. 

So here, the first question you can be asked—because no one will ask what is the class (like it was there that it belongs to C Class, but there is no classes concept here, so no one will ask what is the class of this IP address)—is: "To which network does this IP address belong, and how many hosts are in that network?" 

So you take this `/28` first. 28 means what? Number of continuous 1s, meaning part of Network ID. So the part of Network ID is of how many bits? 28 bits. So what is the part of Host ID? $32 - 28$, that is 4. So the number of bits used to represent the host is 4. So what is the number of hosts? $2^4$, that is 16. So here, my first question that comes is: what is the number of hosts in this network? That is 16.

The next part is that this is an IP address. IP address means what? There is a network of some ABC organization, and in that ABC organization, one IP address is this one (the one with `20.40...`). But what is the Network ID of that ABC organization? Meaning, the whole world doesn't know it by this ID; this is one of the IP addresses in that network, that is `10.20.40`. But to find what is the ID of this network, we do what? We do AND with the mask. 

How did we find the mask in Classful? Each class has its own mask, like Class A has `255.0.0.0`, Class B has `255.255.0.0` (this I have mentioned in old videos of Classes A, B, and C). Here I don't know the mask, but I have already told you what this $n$ is: it is the mask, meaning the number of 1s. You can write it as `11111111.11111111.11111111.11110000`. Why did I write it like this? Because how many numbers of 1s are there? 28. So 8, 16, 24, and 4 is 28. You convert this into a mask; you already know what continuous eight 1s are: `255`. These three become `255.255.255`. 

Now what is this last part representing here? `128`, then `192`, then `224`, then `240`. Meaning here your mask becomes: `255.255.255.240`. This is the mask of this network.

Now here you have to find the Network ID of this IP address—which network this IP address belongs to. So I am telling you a simple concept: in this IP address, you have to start 28 bits from the MSB, meaning you have to start from the very left. Don't even touch the 28 bits; keep 28 bits as it is. 28 bits means what? How many bits in `200`? This represents 8 bits, this represents 8 bits, this represents 8 bits. $8 \times 2 = 16$, $8 \times 3 = 24$. Meaning 24 bits are here. Open only `40`, meaning represent it in binary. If I represent `40` in binary, then what will come? `00101000` ($2^0, 2^1, 2^2, 2^3 \rightarrow 8$; plus $32 = 40$). 

Now what do you have to do? I am telling you a simple method: 28 bits you know is part of the network, and we have already discussed never to change the Network ID, because if the Network ID is changed, then your organization will change, meaning your entire network is changed. So don't touch the network bits. How many bits are there? 28. So these 8 bits, 16, 24, now open this remaining `40` because we have to pick 4 bits here. So 8 bits here, 16 bits here, 24 here, and this comes up to 28, meaning you take it up to `0010`. Now this is a total of how many bits? 28. Meaning these bits you don't have to touch. 

Remaining are how much? These 4 bits remain, and you already know host bits are 4. So these 4 bits will only remain for host bits. Now you make these host bits 0, meaning make all host bits 0. I will convert this into `0000`. Write the others as they are, only convert this and write the octet before this as it is. What is the octet before? `0010`. Meaning, write the above bits as they are (`0010`), and convert these 4 bits into `0000`. 

Due to this, what will happen? You will find out the network of this IP address. So just write `200` as it is, write `10` as it is, write `20` as it is, but this remaining portion becomes how much? `00100000`, which is `32`. So yes, I got the Network ID or Block ID of this IP address. And what is the Block ID? `200.10.20.32`. Don't forget to put `/n`, which is `/28`. So here a very important point I come to know: the network to which this IP address belongs—the whole world knows it by which name? `.32/28`. So I have found out the network of this IP address.

If you want to follow the second method, that is also a simple, similar type of method. You found out the default mask. With this mask, you AND this IP address. If I do AND, let's say—mask we found out, we wrote 28 bits of continuous 1s as this which I just said (`255.255.255.240`), and the IP address is `200.10.20.40`. If you convert `40`, then `40` will be `00101000`. Now perform the AND operation on it: `1 AND 0 = 0`, `1 AND 0 = 0`, `1 AND 1 = 1`, `1 AND 0 = 0`, and the rest are `0`. If you convert it into decimal, it will come out to be `32`. So you either do AND with this or remember as it is that you don't touch these bits and simply convert host bits into 0. You can follow either of the 2 methods; your answer will be the same. 

This is why CIDR (Classless Addressing) concept is very important, and many times questions come in the exam on this. The first question you may get is that you have to find out the network that this IP belongs to and what the number of hosts in it is. We found that out. And which block or network this IP address belongs to—we found that out too.

The last point here I will tell you are the rules. Here are the rules for Classless Addressing:
1. **Addresses should be contiguous:** Meaning all the addresses in that block should be contiguous.
2. **Number of addresses in a block must be a power of 2:** Addresses should be contiguous means like if the address is `200.10.20.32`, then after that `33, 34, 35, 36`—this way they should be contiguous. In between, it should not interleave, meaning nothing should skip in between. If it does, then according to CIDR, it is not valid. Number of addresses means in this block, like if I talk about this, how many hosts are in this block? 16. Meaning how many IP addresses we can generate in this network? 16. And the 16 value is a power of 2 ($2^4 = 16$). So yes, the second point is also valid according to that. If I say that the number of addresses in a network is 17, then 17 is not a power of 2, so this will be invalid.
3. **First address of every block must be evenly divisible by the size of the block:** Meaning whatever network you are talking about, its first address (and what will the first address show? The network). So the ID of that network should be divisible by the size of the block. 

Now here if you see, how can you do it? I'm telling a simple method. You have found this out; this is our first address. This `32` that came—this is the first address of this network because it is the Network ID. If you divide this, what is the size of the block? The size of the block is 16. So you don't have to divide as it is with 16; to divide it, what you have to do is a simple method. The last octet—meaning this 16 value is $2^4$, so these 4 bits here should be 0, meaning the last 4 LSB (Least Significant Bits) should be 0. 

Meaning if you open `32`, then what will it be? `32` is `00100000`. Now here what is the size of the block? Block size is $2^4$. So to do this, you don't have to divide by 16; $2^4$ means you simply take these 4 bits, the last 4 bits. That is the LSB. So if the last 4 bits are 0, that means it is evenly divisible. If this IP address was `33`, then in the case of `33`, what would come here? `00100001`. That's what `33` would be. And if you divide `33`, are the last 4 bits 0? No. The last 4 bits are not coming as 0. So this is how you can find out whether the first address is divisible by the size of the block or not.
