A computer network is a collection of various computing devices. The purpose of a computer network is so that the devices can share data. This means we have to connect various homogeneous and heterogeneous kinds of devices. The main part of a computer network is to share data. 

In a computer network, we have one sender and one receiver. The sender is trying to send some data to the receiver. The sender and receiver can be a machine, or it can be a user who is sending the data through a machine. So we can say the sender is writing a program to send some data to the receiver. Now, how will it send the data? It needs some kind of connection. Connections can be wired or wireless. Whatever the connection is, whether it is wired or wireless, first of all, we need some connection. Through the connection, the packets and data will move from the sender machine to the receiver machine.

Let's say the sender has sent some data, for example, a message "M", and the sender is sending this message "M" to the receiver. The receiver gets the data, which is the message "M". Now, the next part is: whatever message is received by "R", we must check whether "R" is able to read or understand the data or not. The concept says that the data sent by the sender must also be understood by the receiver. For that, there must be some kind of protocol running at the sender's machine and at the receiver's machine. What is the advantage of this protocol? The protocol is like a set of instructions. The sender will send the data, but it will follow some kind of instruction so that whatever data it is sending, the receiver must be able to understand it. 

For example, let's say I make a call. Suppose I know Punjabi and I call a Telugu person. Whatever I am speaking, that person is able to hear it, and he can understand that I am saying something. But is he able to understand whatever I am speaking? No, he is not able to understand, and I cannot understand whatever he is speaking, but I can recognize that he is sending some message. What the connection does is allow data to travel from sender to receiver, or receiver to sender. However, to check whether we are able to understand the data or not, there must be some kind of protocol running on both sides, and that is called proper communication. This means a connection with a proper protocol and set of instructions, if followed, ensures proper communication between the sender and the receiver.

We talk about a sender and a receiver, or in computer network terms, we use "client" and "server" as well. Where are these clients and servers present? One scenario is that the sender and receiver, or client and server, are both present in the same machine. Let's say there is a machine, such as your laptop. In your laptop, a process generated by a client or sender is sending some message to the receiver. For example, if I press a button on the keyboard, whatever I entered will be printed or visible on the monitor. There is a process generated by the sender or a user, and that message is given to the receiver. The sender is generating a process of pressing a button, and the receiver is the monitor, while the sender is the keyboard. 

Here, there is a single person and the same user, but the point is that there is a user process sending some kind of message, and that message is printed on the monitor. However, this concept takes place within the same machine—we are talking about one machine only. When a process communicates with another process in the same machine, that is called inter-process communication. Does this inter-process communication deal with computer networks? No. Computer networks do not deal with that part. This part is handled by the operating system. The kernel in our operating system deals with how a process passes instructions or messages to another process, or how a keyboard passes instructions or messages to the monitor. We call this inter-process communication. 

Obviously, there are some wires involved here too. If you check your CPU, keyboard, or laptop, there are wires at the backend through which data travels. The physical concept of moving data is the same, but there is no concept of a computer network. The concept of a computer network comes into play when the client is on one machine and the server is on another machine. This means they are physically separated—they are different devices where the client and server reside on different machines. Let's say this is machine one and this is machine two. Here, the concept of a computer network applies.

If I talk about my laptop, when I easily press a button or click the mouse, the message appears on the monitor smoothly. That means there is a very smooth connection. I have to create that same smooth connection between a client and a server. It may be possible that one client is in India and the server is in the USA, UK, or some other location. I am not talking about distance; the distance can be 1 kilometer, 1 meter, or even 10,000 kilometers. Distance does not matter, and we are not focusing on distance here. We are saying that the client is present on one machine and the server is present on another machine. In that case, can I make a smooth connection like that and communicate smoothly? To make it smooth, we use the concept of computer networks.

Suppose this is my machine and I am in India, and this is another machine located in the USA. My client machine is sending some data to the server. For example, I am opening my Facebook account. I am not going into deep detail about computer networks for now; I am starting with the very basic level that we use daily. We open Google and Facebook daily. Even today, Google is so famous that if we want to check whether our internet is working, we open Google. That is the fame of Google! So what are we doing with Google or Facebook? We are sending a message from our machine to the Facebook server. There is a Facebook server present in the USA, and my message is reaching there. 

However, as a user, we have to provide an environment to both of these machines. We have to provide such an environment that they do not feel like they are two different machines. This is what we generally experience. When I log in to Facebook through my machine, or when I use WhatsApp or Google, we feel how fast the data arrives. We feel like the data is already on our laptop. That is how fast data gets accessed, similar to accessing movies from the C drive or D drive of a hard disk. If I access a movie in the D drive and click play, the movie starts running through VLC in a fraction of a second. Accessing data from Facebook or Google takes a similar amount of time. 

What is this? We are trying to create a scenario where we are not consciously thinking that we are calling data from the USA or UK, because we do not need to know that. This is a kind of abstraction for us. At that point, the computer network makes my process and the server's process feel as though both are present in the same machine, even though they are not. The main functionality of a computer network is that the client and server, which are physically separated, should feel that they are present in the same machine. Both processes should feel that they are on the same machine, even though they are actually separate. The computer network provides this functionality.

The data that we send to the server, or retrieve from the server—well, the server can also reply. Obviously, if I have requested data from Google or my Facebook account, the server will respond to me with that data. Therefore, we use a lot of functionalities in this two-way communication. What kind of functionalities are generally used? There are basically two kinds of functionalities: mandatory and optional.

Mandatory functions are those that we cannot neglect whenever our client machine sends data or a request to the server. An example of a mandatory function is error control. Error control means ensuring that the message I am sending to the receiver or another machine is the exact same message that arrives, rather than a corrupted one. Because the internet we use today is an open system, it is possible that problems could occur with the message in transit due to noise, hacking, or other factors. If I send message "M", the receiver should receive message "M". But due to noise or other factors, it might change. At the very least, my mechanism should be able to tell me that there is an error. Once I find the error, I can correct it or resend the data. So, error control is one mandatory functionality. 

Another mandatory functionality is flow control. Flow control means regulating the amount of data being sent. As a sender, I cannot just send data endlessly and flood the entire network. There are constraints in place. If we use these constraints, our network will flow properly; otherwise, there are chances of congestion. The protocols running in our system provide these mandatory functionalities.

Yet another mandatory functionality is multiplexing and demultiplexing. Multiplexing and demultiplexing means that when a lot of programs or processes are running on my machine—such as working on different web browsers or downloading things—this feature helps identify which specific process is sending the data. This is basically a transport layer concept which we will discuss in detail later. Similarly, when a message arrives at my machine, such as receiving an email, determining which particular process it should go to is also a key point. Therefore, we keep this as a mandatory functionality as well.

Moving on to optional functionalities, the major one is encryption and decryption, which we also call cryptography. Cryptography means we are not sending the data as-is; we are trying to send it in an altered form so that any intruder in the middle cannot understand it. However, not all applications require encryption and decryption. Nowadays, applications like banking or any money transfer application definitely need some kind of encryption method so that no intruder can hack the data in transit. 

However, this increases the system's complexity. Normal algorithms work fine, and the code for all mandatory functions is already present in our kernel or operating system. If we also code optional functions in the middle, the system's complexity increases, and the time required to send data also increases. This is a crucial point: if we are sending data over normal HTTP, it is not required. But HTTPS encrypts the data before sending, so we definitely need encryption there. If we are sending data normally where we do not need security or cryptography, we can simply send the data without it.

Another optional functionality is checkpoints. Checkpoints mean that when we are downloading data, checkpoints are placed after a certain amount of data is transferred. Suppose I have a 500 MB file and I am downloading it. When 301 MB has downloaded, the download fails. The next time I start the download again, it should not start from zero; it should resume from 301 MB, or perhaps a slightly lower value if checkpoints are set every 100 MB. In that case, if the download fails, it will restart from 300 MB. 

Is this required for all applications? No. If we are requesting a very small amount of data, such as sending a message on WhatsApp where we send data in bytes only, we do not need checkpoints there. It is much better not to add extra functionalities when they are not needed, because they make the system much more complex.

We are discussing these concepts because we are moving toward the OSI model. There are more than 70 functionalities divided between optional and mandatory categories. Because there are so many, a standard model was created for all these functionalities. When discussing networks, the concept of the OSI model comes up at the beginning, alongside the TCP/IP model, and there are many videos and materials available about them. However, sometimes no one tells us *why* there is a need for the OSI model since it is a theoretical model. What is the need for that model? Why are we implementing it? The reason behind that model is this: all the functionalities that we provide are organized into a standardized model so that whenever data is sent from my laptop, it follows this model.

It means I'll follow a standard or protocols, and after following those protocols, my message will go out of my machine. And the same way, when that message is entering the receiver's machine, then it will follow those protocols before reaching the user. 

For all this, we make a model here, and it's a very standard model, i.e., OSI (Open Systems Interconnection). That's an OSI model. Now, what we did in an OSI model, we converted all these functionalities into layers. How? Standard layers of the OSI model are: there are 7 layers. First one is the physical layer. Above the physical layer comes the data link layer, then network layer, transport layer, session layer, presentation, and application. 

So these 7 layers are the heart of the OSI model. All the functionalities I have—around 70 functionalities are there—they simply divide into each of the layers. So whenever my message will be sent by my machine, whenever I'll send a message, then it will pass through all the layers. This is the concept of the OSI model. So the OSI model is fulfilling all the functionalities that are there. 

There are many more models other than this, like the TCP/IP model, which is also very important. The IEEE model is also very important. But from our GATE point of view, or normally academically, we follow only these two protocols.
