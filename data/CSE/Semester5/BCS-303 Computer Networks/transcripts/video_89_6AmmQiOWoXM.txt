Hello friends, and welcome to Gate Smashers. Today's topic is Symmetric Key Cryptography. 

What is the meaning of a symmetric key? It means using the same key—meaning we use only one key. Let us say a sender wants to send a message to a receiver. As we discussed earlier, the sender and receiver always use an unsecured channel. If we are using the internet, that is an unsecured channel. What is the meaning of this unsecured channel? It means there is no dedicated line between us and the receiver. There is no dedicated link. If we send a message to California from here, we know there is no direct line or wire running from my house to California. We are using an unsecured channel, and we do not even know, when the message leaves our system, which node it will go to next.

Because we are using this unsecured channel, we do not send the message in normal plain text. Instead, we encrypt that message with a key. Let us say I am encrypting the message with key $K_1$. We have different symmetric key algorithms (symmetric key meaning the same key is used), such as DES (Data Encryption Standard), Triple DES, and AES (Advanced Encryption Standard). These are different methods used in real life. 

A 56-bit key is used in DES. In Triple DES, a 192-bit key is used. AES has different versions, where the minimum is a 128-bit key and the maximum is a 256-bit key. If we talk about a 56-bit key, it means there are $2^{56}$ possibilities. If someone is applying a brute-force method—brute force meaning checking all permutations from 000 to 111—they would have to check so many values. 

To do this, we use a key to encrypt the message and convert it into ciphertext. I then send this ciphertext to the receiver. The receiver will take it and use the same key, $K_1$, that was used for encryption to decrypt it. After converting it back to the message, $M$, and reading it, the process is complete. Symmetric key cryptography is an easy method that was used before asymmetric cryptography came along.

The big challenge in symmetric key cryptography is key exchange. What does key exchange mean? Let us say I lock my house, and after a while, someone else comes. If they want to unlock it, they need the same key that I used to lock it. Now, there may be a case where there is a duplicate key—he has one and I have one. But if we remove that case, there is only one key to lock and unlock. If I lock it and leave, how will he unlock it? If I put the lock on and leave the key in the lock, then why did I lock it in the first place? Or else, I have to give the key to that person before I leave. To deliver the key, it is obvious that I had to meet him at some point. Can I just send him the key? No. 

So, the biggest challenge in symmetric key cryptography is the exchange of the key. When sending a message to someone, you also have to give them the key, but you cannot send the key along with the message. If I send the key along with the message, then anyone can intercept it, use that key, and decrypt the message. This is the biggest challenge. We use different methods to solve this, such as the Diffie-Hellman key exchange. This is a method by which we can securely exchange keys. These are real-life encryption methods that use the symmetric key approach.

The most important point here is that we use the same key. Apart from this challenge, there is another question that has appeared in the GATE exam and also in the UGC NET exam. Let us say we have four devices connected together. If we have four devices connected together, how many symmetric keys will we need? 

If only two devices are connected, how many keys are needed? Just one, because the key the sender uses to encrypt is the same key the receiver uses to decrypt. Even if the receiver wants to send a message back, they will use the same key, so one key is enough for both. But if the number of nodes is four, how many keys do we need? In this case, the number of keys needed is given by the formula $^NC_2$. This is actually the formula for the number of edges in a complete graph. 

What does $N$ stand for? $N$ stands for the number of vertices (or devices). If we talk about this graph, let us say we have four nodes or devices: $d_1$, $d_2$, $d_3$, and $d_4$. How can these four devices be connected to each other? To connect them fully, $d_1$ and $d_2$ are connected, and so on. Between $d_1$ and $d_2$, there will be one key. We will have one key here, one key here, one key here, and apart from these, two diagonal keys here. This means a total of six keys are needed. 

Using this method, no matter what number of devices is given—let us say 20 devices are connected with each other—the maximum number of symmetric keys needed would be $_{20}C_2$. This is the formula you need to remember. This is more than enough for the UGC NET and GATE exams. In addition, we can also study a little bit about DES, its steps, and how it performs encryption. But this is the basic introduction to symmetric key cryptography. Thank you.
