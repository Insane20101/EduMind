Hello friends, welcome to Gate Smashers. The topic is presentation layer: the presentation layer and its responsibilities. 

The first and very important responsibility is code conversion. Code conversion means, let's say, two machines, M1 and M2. Machine M1 is using the ASCII code—meaning some application is running on M1, and that application is based on ASCII code. There is another machine, M2, and in M2 there is some application which is using the EBCDIC code. Now, whenever we are sending the data to this machine or this particular application, it will send the data in ASCII format. So, when the data comes in ASCII format, how to convert that data into EBCDIC code? Because this machine is understanding the EBCDIC code. For that, we use the presentation layer. Same in this case: this is sending the data in EBCDIC code, but this machine is understanding the ASCII code. So, how to convert EBCDIC code to ASCII code, or ASCII code to EBCDIC code? For that, the presentation layer is used. And this is the major responsibility of the presentation layer: to format the data. This means the application layer gets help by this, so that any data that is coming to the application layer is already converted into whatever format the application wants to read, so that the data is properly visible to the user and can be read properly.

The second responsibility is encryption and decryption. This is very popular nowadays. Encryption has been used for a long time, but it is being used a lot now because the topic of cyber security is trending. So, there we use encryption and decryption. This means the data a machine is sending to another machine, or sending to multiple machines—I am just taking the example of two machines, but you can say a lot of machines are there because we are taking the example of the internet. On the internet, data is open. If I am sending some of my data there, there are a lot of vulnerabilities, there are a lot of threats over there. Now, to remove that from there, I have to achieve confidentiality. Confidentiality means nobody should be able to read my data. You can keep all the security you want, but there is still one or two loopholes that a hacker can find, and through those loopholes your packets or your data could be hacked. But even after that, even after hacking your data, if he is not able to read the data, he cannot get any advantage. How is it possible that he cannot read? If I send my data as plain text—meaning the data that I have written—if I send that data, then obviously any person can simply read that data. But if I send it in the form of cipher text, then no one will be able to read that data. Meaning, if I encrypt that data with a key, and when that data reaches the receiver, the receiver uses the same key (or it depends on symmetric and asymmetric, that we will discuss in detail further; here we are discussing just a basic point), we use encryption and decryption for security purposes. Meaning when we send the data across the network, and we can keep the passwords in our machine by encrypting, so that is called encryption and decryption. And this is the responsibility of encryption and decryption.

Third is compression of data. Compression means sometimes many things, many bits are redundant in our data. That value we can compress by removing those values. Although it is a little tricky, like when we create zip files, the size of the normal file is decreased a little. The empty spaces or the multiple values that are written—what it does is, it removes them. It can also cause problems; loss can also happen, or it may not happen. When you unzip the file, you may face the loss of some data. So that is called compression. So data compression is also the responsibility of the presentation layer. 

So this is all about the functionalities of the presentation layer, and it basically helps the application layer so that it can properly represent the data. And the important part is: the coding of the presentation layer is not the responsibility of the operating system. Meaning its code is not present in the operating system; it is the responsibility of that application, the application that I am using. Generally, if you check in Chrome or Firefox, when we check SBI online banking or OBC online banking, you can check there where you see `http://obc` or `http://sbi.com`. There is one icon present there. If you press that icon, details are shown there. Certificate details are shown there: which encryption method it is using, which encryption/decryption, what key it is using. 

Meaning we have to properly present the data, but who is responsible for that? The application layer. Meaning the person who is making that application, it is his responsibility to code the presentation layer. Meaning whatever he wants from that presentation layer, he should decide himself. Some app may require everything, some app may require one or two things, or some app may not require anything; that depends. So this is not the responsibility of the operating system to provide these three things. It is the responsibility of the application layer. The application layer decides itself what functionalities it wants. But for general sake, if asked about the presentation layer, you can explain these three functionalities.
