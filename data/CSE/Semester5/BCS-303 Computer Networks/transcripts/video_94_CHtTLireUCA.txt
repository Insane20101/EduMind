Next, we will discuss proxy firewalls, also known as application gateways. This represents the next level of security, operating at Layer 5. According to the TCP/IP model, the physical, data link, network, and transport layers are already handled by packet filtering. The remaining layer is the application layer. The proxy firewall checks this application layer data. Because we are passing messages, it scans both the header and the actual data payload to check for malicious words or any content deemed suspicious.

To illustrate, let us look at how user data, such as usernames and passwords, is handled. Today, most websites, payment portals, and online reservation systems require you to enter a username and password. All of these requests go through the HTTPS (Hypertext Transfer Protocol Secure) protocol, which implements Secure Sockets Layer (SSL) security. This ensures your username and password are passed in an encrypted form rather than plain text. 

When this request is sent, it first goes to the network firewall, which checks the IP address and the port number. If the request fits the network firewall's rules, it proceeds to the next level: the proxy firewall. The proxy firewall checks the actual data, including the username, user ID, and password, to verify if the user is authenticated and valid. If the user is valid, they are granted a secure session to access the web service, main server, or database. If the user is invalid, the request is dropped.

For a simple example of deep scanning, consider email. In Gmail, you sometimes find certain emails in the junk folder. Gmail checks for a variety of keywords. If a keyword like "attack" or something similar that does not fit their criteria is found inside the email, deep scanning flags it. Additionally, the firewall checks for out-of-sequence packets. For example, if your packets are arriving in sequence (such as 240, 241, and 243) and an out-of-sequence packet like 1080 suddenly arrives in the middle, the system will drop that packet.

Generally, we use firewalls—whether packet filtering or proxy firewalls—to protect against Denial of Service (DoS) and Distributed Denial of Service (DDoS) attacks. A DoS attack involves repeated requests sent from the same IP address, whereas a DDoS attack involves repeated requests sent from many different IP addresses. The firewall attempts to block these packets according to its rules to keep your network completely secure.

Another point regarding proxy firewalls often confuses students who use proxies on their own systems. For instance, in colleges or universities, access to social networking sites like Facebook is often blocked. Students sometimes use proxies or VPNs to bypass these restrictions. While a college network might block requests sent from your local IP address to Facebook, a Virtual Private Network (VPN) creates a tunnel so you can work virtually from another IP address. These types of proxies encapsulate your normal IP address to bypass the firewall. That is a different concept from a proxy firewall.

In contrast, the proxy firewall we are discussing here checks the user's data and works across all layers up to the application layer. It has the capability to inspect data, perform deep scanning, and check keywords to ensure the entire network remains secure. This covers the types of firewalls. Thank you.
