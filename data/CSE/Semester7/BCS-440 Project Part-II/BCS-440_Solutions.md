## Detailed Step-Wise Solutions — UNIT I: Project Design and Planning
### Section A: Definitions & Concept Questions

**Q1. [Unit I | Topic: Project Design | Type: Theory | Difficulty: Basic]**  
**Question:** What is project design, and why is it important in software development?  

*Concept from scratch:* Project design refers to the process of defining the architecture, components, modules, interfaces, and data for a software system to satisfy specified requirements. It includes not only the technical aspects of the design but also how the system will meet the needs of its users.  

*Step 1 — Importance:* Effective project design is crucial because it serves as a blueprint for the development team, helping to avoid project scope creep and ensuring that all stakeholders have a clear understanding of the project's objectives. Good design also promotes maintainability and scalability of the software.  

*Result:* Project design is essential in software development as it ensures coherence between user requirements and the final product, ultimately leading to successful project outcomes.

**Q2. [Unit I | Topic: Project Planning | Type: Theory | Difficulty: Basic]**  
**Question:** Define project planning. What are the key components of a project plan?  

*Concept from scratch:* Project planning is the process of establishing the scope, objectives, and procedures required to achieve specific goals within a project. It involves identifying tasks, timelines, resources, and responsibilities.  

*Step 1 — Key Components:* The key components of a project plan typically include:  

1. **Objectives:** Clear goals the project aims to achieve.  

2. **Scope Statement:** Defines what is included and excluded in the project.  

3. **Work Breakdown Structure (WBS):** Breakdown of tasks into smaller, manageable parts.  

4. **Schedule:** Timelines and milestones for task completion.  

5. **Resource Allocation:** Identifying and assigning resources needed.  

6. **Risk Management Plan:** Strategies to identify and mitigate risks.  

*Result:* Project planning is crucial as it provides a roadmap for successful project execution and management.

*Result:* Identifying and managing these risks proactively can lead to more successful project outcomes.

**Q2. [Unit II | Topic: Testing Levels | Type: Theory | Difficulty: Basic]**  
**Question:** Define unit testing and integration testing. How do they differ?  

*Concept from scratch:* Unit testing is the process of testing individual components of a software application to ensure they work as intended. Integration testing, on the other hand, tests the interaction between integrated components or systems.  

*Step 1 — Unit Testing:*  
- Focuses on small units of code, typically individual functions or methods.  
- Conducted by developers during the coding phase.  

*Step 2 — Integration Testing:*  
- Focuses on the interaction between integrated components or systems.  
- Conducted after unit testing, often by a separate testing team.  

*Result:* The primary difference is that unit testing verifies the functionality of individual units, while integration testing checks how those units work together.

**Question:** Design five test cases for a login module of a web application.  

*Concept from scratch:* Test cases are specific conditions under which a tester will determine whether an application is working as expected.  

*Step 1 — Test Case Design:*  

1. **Test Case 1:** Valid login credentials.  
   - Input: Username: "user1", Password: "password123".  
   - Expected Result: Login successful, user redirected to dashboard.

   - Input: Username: "user1", Password: "wrongpass".  
   - Expected Result: Error message displayed.

   - Input: Username: "nonexistent", Password: "password123".  
   - Expected Result: Error message displayed.  

4. **Test Case 4:** Empty username and password fields.  
   - Input: Username: "", Password: "".  
   - Expected Result: Error message displayed for empty fields.  

5. **Test Case 5:** SQL injection attempt.  
   - Input: Username: "user1'; DROP TABLE users; --", Password: "anything".  
   - Expected Result: Error message displayed, no database alteration.  

*Result:* These test cases cover a range of scenarios to validate the login functionality.

**Q2. [Unit II | Topic: Bug Tracking | Type: Applied | Difficulty: Intermediate]**  
**Question:** Describe the process of bug tracking and present a sample format for a bug report.  

*Concept from scratch:* Bug tracking is the process of identifying, recording, and managing defects in software during its development and maintenance.  

*Step 1 — Bug Tracking Process:*  

1. **Identification:** Detecting a bug through testing or user feedback.  

2. **Reporting:** Documenting the bug with details for tracking.  

3. **Prioritization:** Assessing the severity and impact of the bug.  

4. **Assignment:** Assigning the bug to a developer for resolution.  

5. **Resolution:** Fixing the bug and retesting.  

6. **Closure:** Closing the bug report once verified as fixed.  

*Step 2 — Sample Bug Report Format:*

- **Title:** Login Button Unresponsive  
- **Description:** The login button does not respond when clicked.  
- **Steps to Reproduce:**  

  1. Navigate to the login page.  

  2. Enter valid credentials.  

  3. Click the login button.  
- **Expected Result:** User should be redirected to the dashboard.  
- **Actual Result:** No response from the button.  
- **Severity:** High  
- **Status:** Open  

*Result:* A well-defined bug report helps in effective tracking and resolution of issues.

### Section C: Advanced Theory & Numericals

**Q1. [Unit II | Topic: Testing Strategies | Type: Theory | Difficulty: Advanced]**  
**Question:** Compare and contrast black-box testing and white-box testing strategies.  

*Concept from scratch:* Testing strategies can be broadly classified into black-box testing and white-box testing.  

*Step 1 — Black-box Testing:*  
- Definition: Testing without any knowledge of internal workings of the application.  
- Focus: Functional requirements and user experience.  
- Advantages: Unbiased testing, end-user perspective.  

*Step 2 — White-box Testing:*  
- Definition: Testing with knowledge of the internal code structure.  
- Focus: Code logic, branches, paths, and conditions.  
- Advantages: Thorough testing of internal operations, identifying hidden errors.  

*Step 3 — Comparison:*  
- Black-box testing is concerned with what the software does, while white-box testing is focused on how it does it.  
- Black-box testing is generally easier and can be performed by testers without programming skills, while white-box testing requires programming knowledge.  

*Result:* Both strategies are essential for comprehensive testing; black-box tests validate functionality, whereas white-box tests ensure code quality.

**Q2. [Unit II | Topic: Continuous Integration | Type: Theory | Difficulty: Advanced]**  
**Question:** Explain the concept of Continuous Integration (CI) and its significance in modern software development practices.  

*Concept from scratch:* Continuous Integration (CI) is a software development practice where developers frequently integrate their code changes into a shared repository, followed by automated builds and tests.  

*Step 1 — Key Elements of CI:*  

1. **Frequent Commits:** Developers commit code changes multiple times a day.  

2. **Automated Builds:** Each commit triggers an automated build process.  

3. **Automated Testing:** Automated tests run with each build to catch issues early.  

*Step 2 — Significance of CI:*  
- **Early Detection of Bugs:** Bugs are identified and fixed early in the development cycle.  
- **Reduced Integration Problems:** Frequent integration reduces the chances of integration issues later.  
- **Faster Release Cycles:** CI supports rapid development and delivery of software.  

*Result:* Continuous Integration enhances software quality and accelerates development processes in modern software practices.
